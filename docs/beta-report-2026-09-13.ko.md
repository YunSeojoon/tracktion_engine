# CoCompose 베타 보고서 — 2026-09-13

`docs/next-milestones-2026-09-12.ko.md`의 B6이 요구하는 "검사 EXE/프로젝트/기기/모델/설정/실제
결과를 연결한 베타 보고서"다. 여기 적힌 것은 **한 실행 파일에서 실제로 일어난 일**이고, 일어나지
않은 일은 통과가 아니라 **미검증**으로 적는다. 이 문서를 쓰면서 새로 빌드하거나 검사를 돌리지

## 3. 어떤 모델로

**이 기계에서 실제로 돌려 본 모델은 로컬 ollama의 `llama3.1:8b` 하나뿐이다.**
`tools/cocompose_bridge.py --provider ollama`로 부른다. hosted OpenAI 경로
(`--provider openai`)는 **여기서 한 번도 호출된 적이 없다.** 코드는 같은 모양이지만 돌려 보지
않은 것은 돌려 보지 않은 것이다.

`test_model_handover.py`와 `test_proposal_boundaries.py`에서 모델 자리에 서는 것은 fixture
bridge다. **그것이 증명하는 것은 앱의 장부 정리이지 누군가의 음악성이 아니다.**

### 모델에 대해 관찰된 것 하나

`llama3.1:8b`는 **자기가 받은 노트 안에 늘 머물지 않는다.** 맥락으로 보여 준 노트를 바꿔야 할
노트로 지목하는 경우가 있다. 앱은 그것을 `OUT_OF_SCOPE`로 거절하고 **음악은 그대로 남는다.**

이것은 통과도 실패도 아니다. `test_ai_connection.py`는 이제 이것을 `observed, not judged`에
적는다. 모델이 무엇을 쓰는지는 실행마다 달라지므로 그것을 통과 항목으로 두면 **그 suite는 날씨를
보고하게 된다.** 앱이 책임지는 쪽 — 모델이 무엇을 쓰든 선 안이거나 이유와 함께 거절되고, 어느
쪽이든 음악은 있던 자리에 있다 — 만 단언한다.

## 6. 제기된 P1과 그 상태

B6은 "미해결 P1이 있으면 새 릴리스 후보로 올리지 않는다"고 적는다. 그래서 리뷰 문서들이 제기한
P1을 **닫혔다고 가정하지 않고 현재 코드에 대고 하나씩 확인했다.**

| 출처 | 내용 | 지금 | 근거 |
|---|---|---|---|
| `docs/review-v4-2026-09-11.ko.md` R1 | 늦게 온 답이 그 사이의 편집을 덮었다 | 고침 | 기준은 질문이 나간 revision. 리뷰 자신의 재현 도구가 `STALE_REVISION`을 돌려준다 |
| 같은 문서 R2 | 첨부가 없으면 범위를 답에서 가져왔다 | 고침 | 답이 적어 온 범위 필드는 읽히기 전에 떼어 내고 첨부에서 다시 세운다. 같은 도구가 `OUT_OF_SCOPE`를 돌려준다 |
| `docs/review-milestones-v3-2026-09-11.ko.md` C1 | 재시작한 bridge가 질문을 다시 보냈다 | 고침 | bridge의 기억은 요청 옆의 답 파일이고 그것은 프로세스보다 오래 산다 — `tools/cocompose_bridge.py`의 `already_dealt_with` |
| 스템 내보내기 | 채널 이름이 같으면 스템 파일이 서로를 덮었다 | 고침 | `examples/CoCompose/Recording.h`의 `uniqueStemName`이 이미 쓰인 이름을 대소문자 구분 없이 세고 `이름 2.wav`로 비켜선다 |
| 렌더 | 실패한 렌더가 지난 WAV를 지우고, 최종 교체가 목적지를 먼저 지웠다 | 고침 | 목적지 옆의 작업 파일에 렌더하고 `moveFileTo`가 아니라 `replaceFileIn`(`ReplaceFile`)으로 바꾼다. 이유는 `Recording.h`의 주석에 적혀 있다 |

여기까지가 **이전 리뷰들이 제기한 P1**이고, 그 목록은 비어 있다.

### 그러나 열려 있는 P1이 둘 있다

`docs/review-v5-2026-09-13.ko.md`가 **오늘**, 이 보고서가 다루는 바로 그 B5 코드에 대해 P1 둘을
새로 제기했다. 그 문서가 가리키는 자리를 읽어 확인했다.

- **R1 — 기존 send의 미리듣기와 적용이 다르다.** 적용 쪽 `Model::addSend`는 같은 대상이 이미
  있으면 level을 갱신한다. 비교본 쪽 `Proposal::applyEffectsTo`는 찾아보지 않고 새 UID의 SEND를
  덧붙인다. 같은 대상에 대한 send 변경에서 **들은 것과 채택한 것이 갈라진다.**
- **R2 — 순환 검사가 send 경로를 따라가지 않는다.** `Model::wouldFeedBack`은 `output`만 따라가고
  SEND 자식을 보지 않는다. A→B send가 있는 상태에서 B→A를 제안하면 **금지한다고 적어 둔 순환
  라우팅이 통과한다.**

둘 다 위의 열두 suite에 **해당하는 자리가 없다.** `test_chain_changes.py`가 보는 것은 효과 하나
추가, send 없는 체인의 순서 변경, main output을 통한 순환까지다. 통과 기록이 이 둘을 반증하지
않는다 — 검사한 적이 없기 때문이다.

**따라서 B6의 규칙에 따라 지금은 새 릴리스 후보로 올릴 수 없다.** 위 표가 말하는 것은 **제기된
P1에 대한 것**이지 P1이 존재하지 않는다는 주장이 아니고, 하루 만에 그것이 증명됐다.

## 7. 확인되지 **않은** 것

아래는 전부 **통과가 아니라 미검증**이고, 각각 왜 기계가 대신할 수 없는지 함께 적는다. 빈 칸이
"아직 안 했다"인지 "할 수 없다"인지 구별되지 않으면 미검증 목록은 쓸모가 없다.

| 항목 | 왜 기계가 못 하나 |
|---|---|
| A/B 청음 | 앱이 하는 것은 두 파일을 만드는 데까지다. 어느 쪽이 나은지는 듣는 일이고 `preview-status.json`에 `heard: false`로 적힌다 |
| 대안 셋이 고를 만한 음악인지 | 보관함이 보장하는 것은 셋이 남아 있고 서로 다른 것을 가리킨다는 것까지다 |
| 실제 모델 둘로의 교체 | 여기서 돈 것은 로컬 모델 하나뿐이고, fixture bridge 둘이 증명하는 것은 앱의 장부다 |
| 타사 VST의 opaque state | 사본의 플러그인에 상태를 세우는 스냅샷 경로를 내장 플러그인으로는 지나갔지만 스캔된 VST로는 한 번도 지나가지 않았다 |
| 메뉴가 포인터 아래 뜨는지, 읽히는지 | 검사는 우클릭이 메뉴 경로에 닿고 곡을 바꾸지 않는다는 것까지만 본다. 어디에 어떻게 보이는지는 보는 일이다 |
| 텍스트 입력란이 진짜로 키보드를 쥔 상태의 `Space`·`Return`·`Home` | 헤드리스 창은 OS 키보드 포커스를 받지 못한다. 가드가 존재하는 이유인 그 상태를 스크립트가 만들 수 없다 |
| 같은 상태의 `Delete`·`Backspace` | 경로가 다르다 — 전역 키 매핑이 아니라 포커스된 컴포넌트의 `keyPressed`이므로 텍스트 박스가 먼저 가져간다. **구조상 안전하다는 뜻이고, 구조를 믿는 것과 확인한 것은 다르다** |
| 100 / 150 / 200% 가독성 | 배율에서 글자가 읽히는지는 보는 일이다 |
| 실제 VST 음색 선택, 건반·오디오 녹음, 재생 중 장치 전환, 인터페이스 분리, 저장·복원 | `docs/acceptance-2026-09-12.ko.md`의 사람 항목이며 전부 비어 있다 |
| 무음이었던 플러그인 여덟의 원인 | 라이브러리를 불러와야 소리가 난다는 것은 아직 추정이다. 음색을 실제로 고른 뒤에도 무음이면 원인이 다른 것이다 |
| **"한 곡을 끝까지" 일곱 줄** | B6의 완료 조건 그 자체다. 일곱 줄 전부 비어 있다 |

마지막 줄에 하나 덧붙일 것이 있다. `docs/review-v5-2026-09-13.ko.md`가 지적하듯 **채팅 패널에
Preview와 후보 선택 버튼이 아직 없다.** 셋 다 진단용 `--ui-script`로만 부른다. 그래서 위 항목 중
몇은 **사람이 아직 안 한 것이 아니라 사람이 마우스로 갈 길이 없는 것**이고, 둘은 구별해서 읽어야
한다.

## 8. CI

**수동 실행 정책은 그대로다.** GitHub Actions는 `Run workflow`로만 돌고 push로는 돌지 않는다.
이 보고서를 만들면서 CI를 실행하지 않았고, 여기 있는 결과 중 CI에서 나온 것은 없다.

## 9. 판정

- **B0~B4는 기계가 할 수 있는 데까지 끝났다.** 경계 수정은 리뷰 자신의 재현 도구가 반박했고,
  메뉴·비교본·보관함·모델 교체는 전부 실제 앱에 대고 도는 검사를 갖고 있다.
- **B5는 구현이 전부 들어왔고 통과 기록도 있다.** 다만 `review-v5`의 P1 둘이 그 코드에 열려 있고
  현재 검사에 그 자리가 없으므로 **닫혔다고 적지 않는다.**
- **B6은 완료가 아니다.** 사람이 채우는 줄이 비어 있고, 특히 "한 곡을 끝까지"의 일곱 줄이 전부
  비어 있다. 기계 검사 520개가 그것을 대신하지 않는다.
- **미해결 P1이 있으므로 새 릴리스 후보로 올리지 않는다.**
