# 사람이 할 일 — 워크플로 마일스톤

작성일: 2026-09-14

[마일스톤](milestones-workflow-2026-09-13.ko.md) W0~W4 가운데 **앱 앞에 앉은 사람만 할 수 있는 일**을
순서대로 한 장에 모았다. 각 절은 "무엇을 / 어디에 적나"만 말하고, 자세한 내용은 해당 문서의 절로
가리킨다. 결과는 이 문서가 아니라 가리킨 자리에 적는다.

## 0. 시작 전

**기준 빌드:** EXE SHA-256 `5e6120c5…`, 커밋 `f5ad83a`. [수용 시트](acceptance-2026-09-14.ko.md)의 기계
절반은 이 빌드 기준이다. 앱을 다시 빌드했다면 시트는 그 빌드의 기록이 아니다 —
`python tools/acceptance_session.py`로 새로 만든 뒤 시작한다.

**왜 사람이 하나.**

- 이 기계에서는 스크립트가 앱 창에 키보드 포커스를 줄 수 없다. `SetForegroundWindow`가 거부됐고
  `AttachThreadInput` 우회도 거부됐다 ([workflow-gaps](workflow-gaps-2026-09-14.ko.md) 「W0 2·3번이 사람
  몫인 이유」).
- 마일스톤이 이 단계들을 진단 스크립트(`--ui-script`) 없이 하라고 정한다.
- 무엇보다 "찾기 쉬운가·편한가·좋게 들리는가"는 입력을 흉내 내서 답할 수 없다.

## 1. W4 열 단계 — 가장 먼저, 한 번에 이어서

**무엇을:** 마일스톤 W4의 열 단계를 앱만 써서 순서대로 한다.

**어디에 적나:** 수용 시트 「처음부터 끝까지 - W4의 열 단계」 표의 결과 칸.

- 막히면 그 줄에 어디서 막혔는지 적고 **뒤 단계는 비워 둔다.** 건너뛴 것은 통과가 아니다.
- 이것을 하면 다음이 대부분 같이 된다.
  - W0 2번 — 시나리오를 실제 마우스·키보드로 따라가기.
  - W1 완료 조건 — AI 없이 악기 → 8마디 → 편집 → 믹서 → Undo/Redo → 저장·출력. **이것은 AI를 쓰지 않는
    구간, 즉 1~5, 9, 10단계에 해당한다.** 6~8단계는 W1 완료 조건에 들어가지 않는다.
- 하는 동안 본 것으로 수용 시트 「AI와 함께 쓸 때」의 `패널 □ × 복원 · 줌 · 스크롤 · 이동/trim`,
  `메뉴가 포인터 아래` 줄도 채운다.

## 2. W0 3번 — 막힌 곳 기록

**무엇을:** 1에서 막히거나 불편했던 자리마다 다섯 가지를 적는다.

| 칸 | 내용 |
|---|---|
| 실제 행동 | 무엇을 눌렀나 |
| 기대 결과 | 무엇이 일어날 줄 알았나 |
| 실제 결과 | 무엇이 일어났나 |
| 우회 방법 | 다른 길로 할 수 있었나 |
| 심각도 | 작업 불가 / 오조작 / 데이터 위험 / 반복 불편 / 시각적 불편 |

형식 예는 workflow-gaps 「W0 2·3번이 사람 몫인 이유」의 표다.

**어디에 적나:** [workflow-gaps](workflow-gaps-2026-09-14.ko.md) 「사람이 아니면 알 수 없는 것」 절.

**함께 판정할 것:** 같은 문서 「이미 있고 닿는데, 찾기 어려울 수 있는 것」 표의 각 줄이 실제로
불편했는지. 그 표는 "여기가 의심스럽다"는 목록이지 판정이 아니라고 문서가 적고 있다. 판정은 써 본
사람이 한다. 표에 있는 수정은 이 판정 뒤에 손댄다.

## 3. 키보드·포커스 — 스크립트로 확인할 수 없는 항목

**무엇을:** 채팅 입력창에 글을 쓰는 중에

- Space / Enter / Home을 누른다. 재생·피아노롤·플레이헤드가 **움직이지 않아야** 한다.
- Delete / Backspace를 누른다. **글자만** 지워지고 클립·노트는 그대로여야 한다.
- Escape를 누른다. 입력창을 **빠져나오되 쓴 글은 남아야** 한다.

**어디에 적나:** 수용 시트 「AI와 함께 쓸 때」 표의 `채팅 중 Space / Enter / Home`,
`채팅 중 Delete / Backspace` 줄. Escape는 표에 따로 줄이 없으므로 `채팅 중 Delete / Backspace` 줄
결과 칸에 함께 적는다.

## 4. 배율 — W2

**무엇을:** Windows 표시 배율 100 / 150 / 200%, 그리고 작은 창에서 네 패널을 본다. 잘리거나 겹치거나
읽기 어려운 곳을 찾는다.

**참고 — 기계 측정 결과.** 기계는 잘리는 글자만 쟀고, 읽기 어려운지는 재지 못했다.

| 조건 | 결과 (필요 px / 가진 px) |
|---|---|
| 100% | 잘리는 글자 없음 |
| 150% | 잘리는 글자 없음 |
| 200% | `Piano roll` 버튼 32 / 25 |
| 700×480 창 | `Remove channel` 57 / 51, `Piano roll` 32 / 21 |

**판단할 것:** Channel Rack 아래 버튼 막대를 좁을 때 아이콘으로 바꿀지.

**어디에 적나:** 수용 시트 배율 표 (100% / 150% / 200% / 작은 창). 위 판단도 해당 줄에 적는다.

## 5. 청음과 실제 장비

**어디에 적나:** 수용 시트의 세 자리. 각 줄의 "어떻게"는 시트에 있으니 여기서는 무엇을 보는지만 적는다.

**「사람이 채우는 항목」 표**

- 악기 음색 선택 — 플러그인 창에서 실제로 쓸 음색을 고를 수 있나
- 음색 바꾸고 바로 렌더 — 들리는 것과 WAV가 같나
- MIDI 건반 녹음 — 친 것이 패턴으로 들어오나
- 오디오 입력 녹음 — 파형이 들어오나
- 재생 중 장치 전환 — 앱이 살아 있고 소리가 이어지나
- 인터페이스 분리 — 앱이 죽지 않고 상태를 알리나
- 저장 / 복원 — 고른 음색과 설정이 그대로인가
- 청음 — 무음·클리핑·끊김·타이밍

**「AI와 함께 쓸 때」 표**

- A/B 청음 — 제안이 더 나은가
- 후보 셋 중에 고르기 — 셋이 고를 만한 음악인가
- 들리지 않는 변경 — Make unique 전후가 같게 들리나
- 서드파티 VST 상태 — A가 바꾼 뒤의 소리인가
- hosted provider — `--provider openai`로 한 번 물어 답이 오나
- 두 모델 교체 — 이전 답이 새 모델 것으로 표시되지 않나

**「무음이었던 플러그인」 표**

- 음색을 실제로 고른 뒤에도 무음인가. 그래도 무음이면 원인이 다른 것이므로 비고에 적는다

## 6. 이미 정해져서 할 필요 없는 것

- **피아노롤 스냅 임시 해제:** Shift 드래그로 결정·구현됐다. 편곡은 Alt다
  ([편집 조작 기본 규칙](editing-rules.ko.md) 「스냅 임시 해제 — 피아노롤은 Shift다」).
- **줌 맞춤 세 명령:** 지금은 단축키를 주지 않기로 결정했다. 써 보고 필요하면 그때 준다.

둘 다 써 보고 불편하면 2의 W0 3번 기록에 적으면 된다.

## 7. 끝나면

- 모든 칸이 채워지면 마일스톤 W0~W4를 판정할 수 있다. **빈 칸은 미검증이다.**
- 채운 문서를 커밋하거나 Claude에게 넘기면, 그 기록을 바탕으로 W1~W3 수정 작업을 이어 간다.
