# CoCompose 재리뷰 및 다음 마일스톤 (2차)

2026-09-10 / 기준 HEAD: 19544c0. 이전 리뷰 기준 5a5f44e 이후 변경을 확인했다. 리뷰 시작 시 작업 트리는 깨끗했다. 이전 문서는 이력으로 유지한다.

## 결론과 검증 범위

N1~N5에 대응하는 구현과 호환성·배포 기록이 추가됐다. 별도 Edit 렌더, 자동화 UI, 녹음 종료 통합, 복구, VST3 식별자 수정, 패키지 검사 gate는 실제 진전이다. 다음 단계는 새 기능 묶음을 크게 늘리기보다 남은 데이터 보존 경계와 배포 실패 처리를 닫는 것이다.

이번에는 최신 코드, JUCE 구현, CI, 작업 기록을 정적으로 확인하고 finish_release.ps1에 작은 실패 보고서를 넣는 실행 검사를 수행했다. 전체 26개 통합 검사, VST 검사, 65분 재생, CI 원격 실행을 이번에 다시 수행하지 않았다. 해당 성공은 docs/worklog.ko.md와 compatibility 문서의 과거 보고다. 무음인 VST가 라이브러리 선택 때문이라는 설명 역시 사람의 음색 선택/청음 확인 전까지 원인 확정으로 취급하지 않는다.

## 발견 사항

### V2-R1 [P1] 최종 WAV 교체가 여전히 기존 파일을 먼저 삭제

위치: examples/CoCompose/Recording.h:498, modules/juce/modules/juce_core/files/juce_File.cpp:300, modules/juce/modules/juce_core/native/juce_Files_windows.cpp:366.

render 성공 후 working.moveFileTo(file)를 사용한다. 현재 JUCE moveFileTo는 대상의 deleteFile 성공 후 moveInternal을 부른다. Windows moveInternal은 MoveFile 호출이다. 따라서 대상 삭제와 이동 사이의 실패 또는 프로세스 종료는 기존 결과물을 유실시킨다. 실패 시 working도 삭제하므로 새 결과까지 없어진다. 임시 렌더 성공은 최종 교체 성공과 다르다.

수정: 기존 대상에는 JUCE replaceFileIn/Windows ReplaceFile 경로 등 삭제 선행 없는 교체를 사용하고 실제 플랫폼 실패 의미를 확인한다. 실패 시 작업 임시 파일을 복구 가능하게 보존할지 정한다.
완료 조건: 기존 WAV 해시를 기록하고 최종 교체 실패를 주입해 기존 파일 보존 확인. 렌더 실패 검사와 교체 실패 검사를 구분한다.

### V2-R2 [P2] 봉인 스크립트가 실패 보고서도 승인

위치: tools/finish_release.ps1:14-17.

스크립트는 Report의 존재만 확인한다. JSON 파싱, 성공 판정, 검사 개수, 검사한 EXE의 해시와 ZIP의 EXE 일치 여부를 확인하지 않는다. 따라서 로컬에서 오래된 보고서나 실패 보고서를 붙이고도 검증된 것처럼 해시를 만들 수 있다. 현재 CI의 선행 step 실패 gate는 존재하므로 CI 전체가 검사를 건너뛴다는 주장은 아니다. 독립 배포 스크립트의 보장이 문서 주장보다 약하다.

실행 재현: build-cocompose/review-seal-91590aefcbbe4ec69d1edf3e9093c380/ 에 dummy.txt만 든 ZIP과 {"passed":false,"checks":[]} 보고서를 만들었다. finish_release.ps1이 exit 0으로 보고서를 첨부하고 SHA256SUMS.txt를 생성했다. 실제 배포 ZIP은 건드리지 않았다.

수정: 검사 보고서에 명시적 결과/schema/검사 대상 EXE SHA-256/커밋을 기록하고, 봉인에서 성공 및 ZIP 내부 바이너리 일치를 검증한다. 필수 추가 문서 누락도 조용히 무시하지 않는다.
완료 조건: 실패·빈·잘못된 JSON·다른 EXE 보고서 모두 거절, 일치하는 성공 보고서만 통과.

### V2-R3 [P2] 제거 실패를 성공으로 보고

위치: packaging/Uninstall.cmd의 detached PowerShell Remove-Item 및 echo Removed 경로.

제거는 2초 후 별도 프로세스에서 수행하고 -ErrorAction SilentlyContinue를 사용한다. 부모 배치는 즉시 Removed/exit 0을 출력한다. 앱 실행 중 EXE가 잠겨 있거나 권한 문제가 나면 실제 파일이 남아도 제거 성공으로 보인다. 바로가기는 먼저 삭제돼 부분 제거 상태가 된다.

수정: 실행 중 앱 확인, 제거 worker의 실제 결과 전달, 실패 시 잔존 경로와 재시도 안내. 자기 폴더 삭제라는 요구는 유지하되 성공 여부를 추정하지 않는다.
완료 조건: 앱 실행 중 제거/잠긴 파일/정상 제거의 결과와 exit status가 실제 파일 상태에 일치. 사용자 프로젝트는 모두 보존.

## 추가 조사 항목 (아직 확정 버그로 분류하지 않음)

- Exporter::~Exporter는 stopThread(30000)를 호출한다. 렌더가 30초 안에 중단되지 않을 때 worker 강제 종료 및 Edit/플러그인 정리 동작을 확인한다. 긴 VST 렌더 중 종료/취소 검사가 필요하다.
- begin은 edit.state.createCopy로 스냅샷을 만든다. 복사 직전 외부 플러그인의 opaque state flush 보장이 보이지 않는다. GUI에서 음색 변경 직후 렌더와 저장 후 렌더가 같은지 검사한다.
- isBusy가 thread running만 보므로 worker 종료 후 takeResult 전 새 export를 시작하는 경계에서 이전 결과가 새 renderEdit 해제와 섞이는지 확인한다.
- Install/Uninstall은 경로를 PowerShell 단일 인용 문자열에 삽입한다. 작은따옴표가 포함된 사용자 경로에 대한 설치/제거 검사가 필요하다.

## 다음 마일스톤

### P0. 데이터 보존과 배포 검증 보강 — 즉시
V2-R1/R2/R3 재현 검사 및 수정. 실제 배포 ZIP을 바꾸지 않는 작은 fixture로 실패 주입을 작성한다.
완료: 교체 실패 시 기존 WAV 보존, 다른 빌드 보고서 봉인 거절, 제거 실패를 성공으로 표시하지 않음. 기존 CI gate 통과.

### P1. 렌더/종료/플러그인 상태 경계
긴 렌더 중 편집·Undo·새 렌더·종료/취소, worker 종료와 결과 수집 사이 요청을 검사한다. 요청별 ID/기준 revision/완료 결과를 일관되게 연결한다. 플러그인 GUI 상태 직후 스냅샷 정확성을 확인한다.
완료: 각 결과가 정확한 요청에 연결되고 취소·종료에서 hang/강제 worker 종료/프로젝트 손상 없음. 활성 프로젝트는 재열기 없이 계속 편집 가능.

### P2. 실제 작곡자 수용 검사
사용자가 쓰는 VST 음색/라이브러리를 실제 선택하고 한 곡을 만든다. MIDI 입력/오디오 입력 각각 녹음, 재생 중 장치 변경, 외부 AI 수정, 저장/복원, WAV 청음을 수행한다. 무음 플러그인은 원인을 확인할 때까지 조건부/미검증으로 표시한다.
완료: 장치·드라이버·버퍼·플러그인/음색·곡 파일·청음 결과가 기록된 재현 가능한 수용 검사. 하드웨어가 없으면 그 항목을 통과로 대체하지 않는다.

### P3. 남은 편집 기능 완결
MIDI learn, 자동화 curve 값의 UI 편집과 실제 곡선 표시, 프리셋 호환 범위/실패 안내를 마무리한다. 스크립트로 함수 호출되는 것과 실제 포인터·키보드 조작 가능한 것을 구분해 화면 검사를 수행한다.
완료: 외부 JSON 수정 없이 곡선 형태를 편집하고 화면과 엔진 평가 일치, MIDI 매핑 저장/복원, 핵심 작곡 시나리오를 마우스/키보드만으로 완료.

### P4. UI 폴리싱과 시각적 일관성
FL 스타일의 Browser·Channel Rack·Playlist·Mixer 정보 밀도를 유지하면서 패널 간격, 글꼴 크기, 색상, 선택/포커스, hover/pressed/disabled 상태를 통일한다. 파형·노트·자동화·미터·노브와 조작 아이콘은 JUCE 벡터/코드로 그려 DPI별 선명도를 유지한다. 이미지 생성 애셋은 시작 화면 아트워크 등 고정 장식에 한정하고 타임라인 배경에 깔지 않는다.

- Browser 검색/빈 목록/누락 샘플, 믹서 슬롯/선택 채널, transport/녹음 상태의 위계를 정리한다.
- 외부 AI 동기화는 적용 중·적용 완료·충돌·저장 대기를 짧고 구분 가능한 상태로 표시한다. 색만으로 전달하지 않고 텍스트를 함께 사용한다. 채팅 UI와 laplas 연동은 이번 범위에 넣지 않는다.
- 툴팁·단축키 안내·키보드 포커스·작은 컨트롤 hit area를 점검한다. 재생 중 매 프레임 전체 패널을 다시 그리지 않는다.
- 1280×720 및 1920×1080, 실제 100/150/200% 배율에서 패널 잘림·스크롤·텍스트 대비를 검사한다. 창 크기 수치만 확인하는 검사와 실제 가독성 검사를 구분한다.

완료: 같은 데모 프로젝트의 전후 스크린샷, 키보드/마우스 작곡 시나리오, 실제 배율별 시각 점검을 남긴다. 컨트롤 기능·라이브 싱크·Undo 회귀가 없어야 한다. 애셋 명세는 docs/ui-polish-assets.ko.md 참고.

### P5. 릴리스 후보 동결
P0~P4 후 특정 커밋의 EXE와 ZIP에 검사 보고서 해시를 연결한다. 깨끗한 Windows 환경, 실제 사용자 환경, CI의 결과를 각각 기록한다. 서명/자동 업데이트는 기존 수동 ZIP 정책을 유지해도 되며 이를 기능 실패로 간주하지 않는다.
완료: 동일한 바이너리를 대상으로 한 보고서, 설치·업데이트·제거와 프로젝트 보존, 알려진 제한 목록을 가진 릴리스 후보 하나를 지정.

진행 순서: P0 → P1 → P2 → P3 → P4 → P5. P2의 장치/청음 준비와 P4의 애셋 준비는 P0과 병행 가능. 새 기능보다 P0/P1을 먼저 완료한다.
