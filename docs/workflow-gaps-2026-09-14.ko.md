# W0 — 실제 작업 흐름의 막히는 자리

## 이 문서가 무엇이고 무엇이 아닌가

[마일스톤](milestones-workflow-2026-09-13.ko.md) W0의 완료 조건은 **"구현해야 할 것과 이미
있지만 찾기 어렵거나 조작이 불편한 것을 구분한 목록"**이다. 그 목록의 절반은 의견이 아니라
사실이다 — 기능이 있는지, 포인터로 닿는지, 스크립트로만 닿는지는 소스에서 판정된다. 그 절반을
여기 적는다.

나머지 절반은 **앉아서 써 봐야 알 수 있는 것**이고, 그것은 여기 적지 않는다. 문서가 금지한
방식(`--ui-script`로 기능에 진입)으로 확인한 것을 "해 봤다"고 적으면 그 목록은 쓸모가 없어진다.
아래 표의 `사람` 칸이 그 자리다.

판정 기준:

| 표시 | 뜻 |
|---|---|
| **없음** | 기능 자체가 없다. 만들어야 한다 |
| **스크립트만** | 기능은 있는데 `--ui-script`로만 닿는다. 마우스로는 길이 없다 |
| **있음** | 포인터나 키보드로 닿는다 |
| **사람** | 닿기는 하는데 편한지 어떤지는 써 봐야 안다 |

## 기능은 있는데 마우스로 길이 없는 것

`--ui-script`에만 있고 화면에 없는 것들이다. 어제까지는 여기에 Preview·후보·A/B 재생도
있었고 지금은 없다.

| 기능 | 스크립트 동작 | 없는 것 |
|---|---|---|
| 프로젝트 메모 — 확정 조건 | `project_note condition` | 조건을 적거나 지우는 화면이 없다. 모델에게는 전달되는데 사람은 자기가 무엇을 정해 뒀는지 볼 수 없다 |
| 프로젝트 메모 — AI 추정 수락 | `project_note accept` | 같은 이유 |
| 프로젝트 메모 — 할 일 | `project_note todo_at` / `todo_on` / `done` | 구간 메모를 붙이거나 완료 표시할 길이 없다. 클립 추적·끊김 표시는 동작하는데 만들 방법이 없다 |
| 변형 강도 | `project_note strength` | 살짝/적극/새로를 고를 곳이 없다. 기본값 `tidy`로 고정돼 있다 |
| 후보 기각 | `candidate discard` | 목록에서 고를 수는 있으나 버릴 수 없다 |
| 자동화 곡선 편집 | `curve_click` / `curve_drag` / `curve_bend` | 곡선은 그려지고 포인터로 점을 찍는 것은 된다. `curve_bend`(구간 휘기)와 `curve_remove`는 스크립트에만 있다 |
| MIDI CC 입력 | `midi_cc` | 검사용이고 실제 하드웨어가 대신한다. UI 없음이 맞다 |

앞의 다섯 줄이 W1/W2에서 만들어야 할 것이고, 그 중 **프로젝트 메모 세 줄이 한 덩어리**다 —
조건·추정·할 일·강도는 같은 곳에 살아야 한다.

## 이미 있고 닿는데, 찾기 어려울 수 있는 것

사실로는 "있음"이지만 W0이 구분하라고 한 두 번째 부류다. **여기 적은 것은 "불편하다"는 판정이
아니라 "여기가 의심스럽다"는 표시이고, 판정은 써 본 사람이 한다.**

| 기능 | 어디에 있나 | 왜 의심스러운가 |
|---|---|---|
| 피아노롤 열기 | 클립 더블클릭, Enter, Edit 메뉴 | 세 길이 다 있는데 셋 다 클립이 선택돼 있어야 한다. 선택이 없을 때 무엇을 눌러야 하는지는 화면에 없다 |
| 구간 지정 | 룰러에서 Shift+드래그 | Shift가 필요하다는 것이 어디에도 안 쓰여 있다 |
| 스냅 임시 해제 | Alt를 누른 채 드래그 | 같은 이유 |
| 이전 줌으로 | View 메뉴 `Back to previous zoom` | 단축키가 없다 |
| 채널 프리셋 | 채널의 `P` 버튼, 채널 헤더 우클릭 | 한 글자 버튼이다 |
| 스텝 길이·피치 | 채널의 `1/16` 버튼 | 같은 이유 |
| 후보 목록 | 채팅 패널 드롭다운 | 제안이 하나도 없으면 나타나지 않는다. 없을 때 "없다"고 말하지 않는다 |
| 오디오 클립 다듬기 | 오디오 클립 우클릭 | Level/Fade/Speed가 고정값 목록이다. 정확한 값을 넣을 수 없다 |

## 사람이 아니면 알 수 없는 것

여기는 비워 둔다. `docs/acceptance-2026-09-12.ko.md`의 같은 항목과 겹치며, 그 문서가 각 줄에
왜 기계가 못 하는지도 적고 있다.

- 선택·이동·줌·스크롤 규칙이 창 사이에서 일관되게 **느껴지는지**
- 메뉴가 포인터 아래 뜨고 문구가 읽히는지
- 100 / 150 / 200% 배율에서 잘리는 곳
- 채팅·이름·수치 입력 중 Space / Delete / Enter / Home
- A/B가 실제로 더 나은지
- 실제 VST 음색, 녹음, 장치 전환, 인터페이스 분리
