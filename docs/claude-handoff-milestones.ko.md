# CoCompose — Claude 인수인계 및 FL 스타일 DAW 마일스톤

작성: 2026-09-10. 사용자 제공 FL Studio 스크린샷을 기능 범위의 기준으로 삼는다. 이미지는 레이아웃과 보이는 조작 요소의 근거이며 숨겨진 메뉴 전체 사양의 근거는 아니다.

## 제품 목표와 고정 요구사항

기존 DAW/VST 사용자가 직접 편집하면서 외부 AI와 함께 작곡하는 Windows 네이티브 DAW. Browser(왼쪽), Channel Rack(가운데 위), Mixer(가운데 아래), Pattern picker와 Playlist(오른쪽)를 동시에 쓰는 FL 스타일 작업 환경을 목표로 한다. 단순히 비슷한 화면을 그리는 것으로 완료하지 않는다. 각 컨트롤이 실제 엔진 상태와 소리에 연결되어야 한다.

- 외부 코드/도구가 음악 데이터를 바꾸면 열린 프로젝트의 UI와 엔진에 반영한다. 앱/프로젝트 재시작을 동기화 방법으로 사용하지 않는다. 약간의 적용 지연과 그래프 재구성 중 짧은 음향 중단은 허용한다.
- 코드가 생성한 프로젝트 데이터의 라이브 적용이 요구사항이다. C++ 실행 파일 자체의 무재시작 교체와는 구분한다.
- AI는 우선 외부에서 연결한다. 앱 내 채팅은 후순위다.
- 사람이 UI로 한 편집과 AI 편집은 같은 데이터 모델·검증·Undo 경로를 사용한다.
- Tracktion Engine/JUCE 기반을 유지한다. FL 고유 플러그인 바이너리를 복제하는 작업은 아니다. 화면에 보이는 음향 기능을 내장 효과 또는 실제 호환 플러그인으로 제공한다.

README.ai-editor.md, docs/windows-guide.ko.md, docs/worklog.ko.md, examples/CoCompose/CMakeLists.txt 수정 및 .github/workflows/cocompose-windows.yml, docs/windows-portable.ko.txt, tools/build-windows.ps1 추가. 덮어쓰거나 reset하지 말고 검토해서 이어받는다.

로컬 CPack ZIP 생성은 성공했다. build-cocompose/dist/CoCompose-0.1.0-windows-x64.zip을 풀면 CoCompose.exe가 압축 해제 폴더 바로 아래에 위치한다. 이전 검사 호출 중 하위 폴더가 있다고 잘못 가정한 호출은 실패했고, 수정 경로의 후속 검사 완료 결과는 인수 시 확인해야 한다. GitHub CI 성공은 미확인. 설치 프로그램·자동 업데이트·코드 서명은 없다.

## 라이브 싱크 계약 — 변경 시 마이그레이션 필수

state.json은 앱이 내보내는 현재 상태, project.json은 외부 입력이다. 외부 도구는 최신 state.json을 읽고 수정한 전체 스냅샷을 project.json에 원자적으로 쓴다. session_id/revision 검증 및 request_id 응답 연결을 유지한다. 앱이 입력 파일을 지속적으로 덮어쓰면 안 된다. 오래된 입력은 거절한다. 배열 누락에 따른 삭제 의미를 확인한다. 현재는 다중 작성자 요청 큐가 아니다.

동일한 Edit 인스턴스에 변경을 적용한다. control.json/control-status.json은 재생·Undo 등 제어, sync-status.json은 적용/거절/저장 실패 상태다. applied_unpersisted와 재시도 동작을 유지한다. 새 패턴/믹서 모델은 schema 버전을 올리고 기존 프로젝트 변환을 제공한다. JSON에 VST 전체 내부 상태를 억지로 펼치지 말고 native 프로젝트에 보존한다.

## 마일스톤과 완료 조건

### M0. 인수·빌드·배포 기준선 확정
- 미커밋 배포 작업 검토, 로컬 ZIP 내부 EXE로 기존 통합 검사 재실행, 성공 결과를 작업 기록에 남긴다.
- Windows CI 빌드와 ZIP artifact 다운로드/실행을 검증한다. 개발 도구 없는 Windows 환경에서 시작 검사를 수행한다.
- 완료: 압축 해제 후 더블클릭 가능, 기존 프로젝트 복원 및 라이브 싱크 회귀 없음. 빌드 실패 시 artifact를 성공으로 표시하지 않는다.

### M1. 작업 공간과 패턴 중심 데이터 모델
- 화면의 4영역 배치, 크기 조절, 숨김/복원, 선택/포커스/단축키, 레이아웃 저장. 상단 기본 메뉴와 transport 연결.
- Channel(악기), Pattern(채널별 노트), Playlist lane, Clip instance(패턴 참조), Mixer insert를 구분한다. 하나의 engine audio track에 모든 개념을 묶지 않는다.
- 기존 클립 모델→패턴 모델 변환과 stable ID, 새 schema, Undo 정책을 구현한다. 재사용 패턴을 엔진 클립에 반영하는 최소 연결부터 검증한다.
- 완료: 같은 패턴 두 인스턴스 수정/Undo 동기화, 독립 복제, 기존 프로젝트 변환, 외부 변경의 즉시 UI 반영. 빈 패널만으로 완료 처리 금지.

### M2. Channel Rack + 피아노롤
- 채널 관리, 실제 VST3/내장 악기, 기본 샘플러, 스텝 on/off·길이, 패턴 선택/복제, 볼륨/팬/mute/solo/믹서 번호.
- 피아노롤 노트 추가/삭제/드래그/길이·velocity, 다중 선택/복제/퀀타이즈/스냅/줌, 키보드 미리듣기.
- 완료: 드럼·베이스·멜로디 3채널 패턴을 UI만으로 작성/재생/저장하고 외부 노트 수정이 열린 에디터에 반영된다.

### M3. Playlist + Pattern picker
- 패턴 드래그 배치, 반복 참조/Make unique, 클립 편집 도구, 레인 관리, 루프/시간 범위, 마디/박자 표시, Song/Pattern 재생 차이.
- 완료: M2 패턴으로 32마디 편곡 작성; 이동/분할/복제/Undo가 소리·화면·state에 일치. 재생 중 외부 배치 변경에 재열기 불필요.

### M4. Browser + 오디오 클립 작업
- 폴더 탐색/검색/최근/즐겨찾기, 샘플 미리듣기, Rack/Playlist 드래그, 프로젝트 자산 및 누락 파일 찾기.
- 파형 표시, 오디오 클립 트림·오프셋·게인·페이드·기본 타임스트레치, 샘플 수집 저장.
- 완료: 외부 WAV 드롭→미리듣기/배치→자산 포함 저장→다른 폴더에서 복원 가능. 잘못된 파일은 기존 프로젝트 손상 없이 거절.

### M5. Mixer + VST/효과 체인
- Master/Insert 실제 미터·페이더·팬·mute/solo, 채널 할당, bus/send, 입출력 선택, 효과 슬롯 순서/bypass/wet-dry, 플러그인 창과 상태 저장.
- EQ/limiter/saturation/delay/chorus/reverb 기능 제공. 우선 기존 엔진 효과를 조사해 재사용하고 부족한 것만 구현한다.
- 완료: 3악기→드럼 bus/send reverb→Master 시나리오가 실제 오디오로 검증된다. 외부 파라미터 편집/Undo 및 프로젝트 복원 후 효과 유지. VST 스캔 실패/누락 대응 확인.

### M6. Automation + 녹음 + 출력
- 파라미터를 자동화 클립에 연결, 포인트/곡선 편집, 재생 평가, MIDI learn/외부 제어 연결을 제공한다.
- MIDI 입력·녹음, 오디오 입력/트랙 arm·녹음, 카운트인/메트로놈, 녹음 클립 배치. WAV 전체/선택 범위 및 stem 출력.
- 완료: MIDI/오디오를 녹음하고 필터·볼륨 자동화를 포함해 WAV 출력; 길이·무음 여부·클리핑 및 들리는 결과 확인. 자동화 중 수동/AI 편집 우선권 명시.

### M7. 외부 AI 공동 작곡 완결
- 확장된 패턴/배치/믹서/자동화에 외부 편집 API 연결. 최소 CLI/파일 프로토콜부터 유지하고 필요 시 명시적 patch/command 계층 추가.
- 수정 전후 diff/적용 결과, 충돌 거절·재읽기, 한 작업 한 Undo, 실패 시 보존, UI 조작과 외부 편집의 충돌 테스트.
- 완료: 외부 에이전트가 열린 32마디 곡의 드럼 변형·베이스 생성·구간 재배치·믹스 조정을 수행하고 사용자가 각각 확인/Undo 가능. 이 단계 전에도 모든 마일스톤의 신규 데이터는 라이브 싱크를 지원해야 한다.

### M8. 화면 기능 동등성 점검과 배포 안정화
- 위 기능 표의 각 행을 실제 데모 프로젝트로 점검하고 미연결 버튼/메뉴를 제거하거나 구현한다.
- 100%/150%/200% DPI, 키보드 작업, 패널 복원, 장시간 재생·저장, 장치 변경, 누락 VST/샘플, 비정상 종료 복구, autosave/history/preset 정리.
- 완료: 깨끗한 Windows에서 ZIP 실행→샘플 탐색→패턴 작성→편곡→믹스/자동화→녹음/렌더→재실행 복원까지 문서만으로 수행. 설치 EXE/서명/업데이트는 배포 채널을 정한 뒤 별도 작업으로 진행.

순서: M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8. M4 Browser 일부는 M2 이후, M5 엔진 라우팅 조사는 M1 이후 병행 가능하다. 일정을 날짜로 확약하지 말고 각 완료 조건을 충족할 때 다음 단계로 넘어간다.

## Claude 작업 방식 및 첫 요청
