# CoCompose 코드 리뷰와 다음 마일스톤

작성일: 2026-09-10
리뷰 기준: HEAD 5a5f44e. a151a52 이후 커밋 로그, 핵심 녹음/렌더/모델/타이머 경로, CI 및 작업 기록을 확인했다. 작업 트리는 리뷰 시작 시 깨끗했다. 이번 작업은 정적 코드 리뷰와 계획 작성이며 앱 빌드·23개 통합 검사·청음·실장치 검사를 새로 실행하지 않았다. 아래 기존 검사 통과는 작업 기록의 보고이며 이번 리뷰의 재검증 결과가 아니다.

## 판단

M0~M8에 대응하는 구현 커밋이 있고 기본 DAW 수직 기능은 크게 진척됐다. 그러나 완료 조건 전체가 충족됐다는 뜻은 아니다. 특히 자동화 곡선 UI, MIDI learn, 백업 회전, 실제 입력 녹음, 타사 VST3, 실디스플레이 DPI/장치 전환 검증이 남아 있다. 20초 재생 검사는 장시간 안정성 검증으로 간주하지 않는다. 다음 릴리스 목표는 기능 수 확대보다 작업 결과 보존과 실사용 검증이다.

## 확인된 리뷰 이슈

### R1 [P1] 동명 채널의 스템 파일이 덮어써진다

근거: examples/CoCompose/Recording.h:318, :379.
Exporter::run은 채널 표시 이름만 정리해 WAV 파일명으로 쓴다. 채널 ID와 달리 이름의 유일성은 보장하지 않으며 render는 기존 파일을 먼저 삭제한다. 동일한 이름의 두 채널을 export하면 두 번째가 첫 번째 파일을 대체한다. 서로 다른 이름도 파일명 정규화 결과가 같으면 충돌할 수 있다. 결과 files에는 같은 경로가 반복돼 성공 개수도 오해를 만든다.

수정: 채널 stable ID 또는 충돌 없는 순번을 파일명에 포함하고, 렌더 전에 전체 출력 경로를 확정/검증한다.
완료 검사: 동명 채널 2개와 파일명 정규화 충돌 사례를 내보내면 서로 다른 파일이 생성되고 각 채널 신호가 보존된다.

### R2 [P1] 렌더 실패 전에 이전 WAV를 삭제한다

근거: examples/CoCompose/Recording.h:377-381.
render가 file.deleteFile()을 먼저 호출하고 renderer 성공 여부는 그 뒤 확인한다. 이미 존재하는 mix.wav를 재출력하다 실패하면 직전 정상 결과물을 잃을 수 있다. 삭제 반환값도 확인하지 않는다.

수정: 같은 디렉터리의 고유 임시 WAV에 렌더하고 성공/파일 검증 후 최종 파일을 교체한다. 실패 시 이전 파일 보존, 임시 파일 정리 및 구체적인 실패 원인을 보고한다.
완료 검사: 정상 출력의 해시를 기록한 뒤 렌더 실패를 주입해 기존 해시가 유지되는지 확인한다.

### R3 [P2] 스템 선택에서 send 경로가 빠진다

근거: examples/CoCompose/Recording.h:316, :359-374; Model.h:907-955.
스템은 채널 트랙과 insert의 output 연결만 따라간다. 실제 믹서에 구현된 SEND target은 addOutputChain에서 방문하지 않는다. 예를 들어 dry insert에서 별도 reverb insert로 send하면 그 효과 리턴이 스템 트랙 선택에 포함되지 않는다. 현재 설명인 효과 체인을 포함하는 스템과 차이가 난다.

수정: dry/wet stem 의미를 명시하고, wet이면 send destination과 그 출력 경로까지 포함한다. 공유 bus의 비선형 효과 때문에 개별 wet stem 합이 전체 mix와 항상 같다고 보장하지 않는다.
완료 검사: 리턴만 들리는 send 설정에서 mix와 해당 wet stem 모두 실제 신호가 나오는지 렌더로 확인한다.

### R4 [P2] CI가 검사를 실행하지 않고 배포 ZIP을 올린다

근거: .github/workflows/cocompose-windows.yml:23-31, tools/build-windows.ps1.
workflow는 build-windows.ps1 실행 후 artifact 업로드만 한다. 빌드 스크립트도 configure/build/CPack뿐이다. 따라서 로컬 통합 검사 23개가 깨져도 컴파일 성공만으로 ZIP이 배포된다.

수정: 압축 해제된 EXE에 대한 portable smoke와 자동화 가능한 통합 검사를 artifact 업로드 전 gate로 추가한다. CI 오디오 장치 제약 때문에 수행할 수 없는 검사는 명시적으로 분리하고 실제 장치 검증과 혼동하지 않는다.
완료 검사: 의도적인 검사 실패 시 workflow 실패 및 배포 artifact 업로드 차단, 성공 시 report/log 보관.

## 추가 조사 필요 — 확정 버그와 구분

- Exporter worker가 활성 Model/Edit를 읽고 렌더하는 동안 Main.cpp:679 이후 타이머는 project.poll과 UI 편집을 계속 허용한다. exporter.isBusy는 주로 상태 출력에만 쓰인다. 렌더 중 외부 편집/트랙 삭제/Undo/종료의 소유권 및 Tracktion의 동기화 보장을 조사해야 한다. 정적 코드만으로 충돌 발생을 재현했다고 주장하지 않는다. 권장 방향은 렌더 시작 시 고정된 프로젝트 스냅샷을 별도 Edit로 렌더하는 것이다.
- Recorder::adoptTake는 모든 녹음 결과를 firstLane에 놓는다. WAV take는 원래 채널 입력의 믹서 경로와 source offset 등 보존 여부를 실녹음으로 확인해야 한다. 기존 합성 MIDI take 검사는 이 범위를 커버하지 않는다.
- 녹음 종료 경로가 메뉴의 Recorder::stopRecording과 외부 control stop으로 다르다. control stop은 transport.stop만 호출한다. 외부 중지에서도 take 편입/클릭 복원이 보장되는지 회귀 검사 필요.

## 다음 마일스톤

### N1. 출력 데이터 보존 및 렌더 경계 (최우선)
R1/R2/R3 수정. 렌더 결과를 요청 ID·기준 revision과 연결하고 부분 스템 실패를 보고한다. 렌더 중 편집·Undo·종료를 재현해 소유권을 확정한다. 활성 프로젝트 재열기로 해결하지 않는다.
완료: 충돌 없는 파일명, 실패 시 기존 출력 보존, wet send 검증, 렌더 중 편집 스트레스에서 프로젝트와 출력 모두 일관성 유지.

### N2. 녹음과 프로젝트 복구
UI/외부 stop을 동일 녹음 종료 경로로 통합한다. MIDI/오디오 입력 선택·arm 상태·take 배치/라우팅·offset 보존을 실장치로 확인한다. autosave 회전, 복구본 선택, 누락 자산 안내를 구현한다.
완료: MIDI 키보드와 오디오 입력 각각 녹음→외부 stop→편집→저장→복원; 실패/강제 종료 후 마지막 복구본으로 작업 보존. 합성 take 검사와 실장치 검사를 별도 보고.

### N3. 화면으로 끝내는 작곡 흐름
기존 M6 미완료인 자동화 곡선 직접 편집(추가/이동/삭제/곡선/Undo)을 제공한다. MIDI learn, preset 저장·불러오기, History/백업 탐색을 완성한다. 원본 스크린샷 기능 표를 클릭/키보드 시나리오로 다시 점검한다.
완료: --ui-script 또는 JSON 수동 편집 없이 샘플 탐색→패턴 작성→32마디 편곡→믹스/자동화→녹음→WAV 출력 가능. 그 상태에서 외부 AI 편집은 같은 열린 UI에 반영.

### N4. 실제 환경 호환성·장시간 안정성
사용자의 실제 VST3 목록과 오디오 인터페이스로 호환성 표 작성. 플러그인 scan/창/상태 복원/자동화/렌더, 장치 전환, 실제 100/150/200% DPI, 반복 저장/Undo 및 1시간 이상 재생을 검사한다. 사람이 결과 WAV를 청음한다.
완료: 앱/플러그인 버전·장치·샘플레이트·버퍼·재현 절차·결과가 기록된 표와 버그 목록. 장치가 없으면 미검증으로 남기고 완료 선언하지 않는다.

### N5. 검증된 Windows 릴리스
R4 CI gate를 먼저 추가하고 앞 단계마다 사용한다. 최종 단계에서 깨끗한 Windows 설치 환경의 ZIP 검사, 버전/커밋/해시·변경 기록·검사 보고서를 묶는다. 사용자 배포 방식에 따라 설치 EXE/바로가기/제거 기능을 추가하고 코드 서명·업데이트 채널은 명시적으로 결정한다.
완료: 테스트 실패 ZIP은 배포되지 않으며 사용자는 개발 도구 없이 설치 또는 압축 해제 후 실행 가능. 업데이트 후 기존 프로젝트 보존.

순서: N1 → N2 → N3 → N4 → N5. CI gate는 N1과 함께 착수한다. 이번 리뷰 문서 외 소스는 수정하지 않았다.
