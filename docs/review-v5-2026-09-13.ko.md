# CoCompose 재리뷰 — 2026-09-13

기준 커밋: `86d9bba0cc87f71a1e8e3d93b88b92549cd433b5`.
이번 검사는 최신 B5 체인/Send 변경 코드와 기존 테스트를 읽은 정적 리뷰다. 새 EXE 빌드, 앱 실행, 청음 또는 테스트 실행 결과로 해석하지 않는다. 기존 작업 트리 변경은 보존했다.

## 발견 사항

### R1 · P1 — 기존 Send 변경의 미리듣기와 실제 적용이 다르다

- 위치: `examples/CoCompose/Proposal.h:369`, `examples/CoCompose/Model.h:354`.
- 조건: A에서 B로 level=0.25인 Send가 이미 있고, 같은 대상에 level=0.5인 `send`를 제안한다.
- 실제 적용은 `Model::addSend`가 기존 대상의 level을 갱신한다. 미리듣기의 `Proposal::applyEffectsTo`는 기존 Send를 찾지 않고 새 UID의 SEND를 추가한다. `syncSends`는 UID별로 플러그인을 만들므로 복사본에는 두 Send가 남는다.
- 결과: 사용자가 비교한 B와 채택 후 라우팅/레벨이 다르다. 동일 제안 안에서 같은 대상을 두 번 설정해도 이 차이가 발생한다.
- 수정 방향: detached tree와 실제 적용 양쪽에서 동일한 Send upsert 규칙을 사용한다.
- 회귀 조건: 기존 Send 레벨 변경 및 동일 대상 연속 변경에서 preview/apply의 대상별 Send 수와 최종 level이 같아야 한다. 적용 후 렌더 비교와 한 번 Undo도 확인한다.

### R2 · P1 — 순환 검사가 Send 경로를 누락한다

- 위치: `examples/CoCompose/Model.h:375`, `examples/CoCompose/Tools.h:772`.
- 조건: A와 B의 main output은 master이고 A→B Send가 있을 때 B→A Send를 제안한다.
- `wouldFeedBack`은 `output`만 따라가고 SEND 자식을 탐색하지 않아 위 연결을 허용한다. `syncSends`도 같은 검사에 의존한다. 또한 제안의 체인 항목은 모두 변경 전 모델에 대해 따로 검사하므로 한 제안에 A→B와 B→A를 넣는 경우도 놓친다.
- 결과: 금지한다고 명시한 순환 라우팅이 프로젝트에 들어간다. 엔진에서 어떤 소리/차단 현상이 발생하는지는 이번에 실행 검증하지 않았다.
- 수정 방향: main output과 Send를 포함한 그래프를 검사하고, 제안을 임시 상태에 순서대로 반영한 결과까지 검증한 뒤 쓰기 시작한다.
- 회귀 조건: 기존 Send를 통한 역방향 연결, 다단계 순환, 한 제안으로 생기는 순환 모두 거절하고 revision/프로젝트가 그대로여야 한다. 정상적인 비순환 Send는 허용한다.

### R3 · P2 — 이펙트 순번을 전체 자식 순번으로 사용한다

- 위치: `examples/CoCompose/Tools.h:672`, `examples/CoCompose/Proposal.h:393`.
- `readEffectChange`는 EFFECT만 센 순번으로 `to`를 검증하지만 적용에서는 EFFECT와 SEND가 섞인 Insert에 그대로 `moveChild(i, to)`를 호출한다.
- 조건: 자식 순서가 `[Send, Delay, Reverb]`이고 Reverb를 이펙트 순번 0에서 1로 옮기는 두 동작을 차례로 수행한다. 첫 이동 후 `[Reverb, Send, Delay]`, 다음 이동 후 `[Send, Reverb, Delay]`가 되어 두 번째 이동은 이펙트 순서상 실행되지 않는다. 더 단순하게 `[Send, Reverb, Delay]`에서 Reverb를 `to=1`로 옮겨도 순서가 그대로다.
- 결과: diff가 약속한 체인 순서와 실제 체인이 다를 수 있다. preview와 apply 양쪽에 같은 문제가 있다.
- 수정 방향: EFFECT 순번을 실제 자식 위치로 변환하거나 EFFECT 순서만 재구성한다. 양쪽 적용 경로에 같은 규칙을 사용한다.
- 회귀 조건: Send 추가 후 효과 추가로 섞인 체인에서 모든 효과를 양방향 이동하고, inspect 순서/렌더 체인/Undo를 확인한다.

## 진행 상태와 검증 공백

클립 move/copy/remove/make_unique, effect add/remove/move/bypass, Send 변경까지 제안 경로가 확장됐다. 이는 구현 범위 확대이며 B5/B6 전체 완료 판정은 아니다.

`tools/test_chain_changes.py`는 단일 효과 추가, Send 없는 체인 순서 변경, main output을 통한 순환을 검사한다. 위의 기존 Send 갱신, Send 기반 순환, 혼합 자식 순서는 현재 검사에서 빠져 있다.

`ChatPanel.h`에는 Ask/Apply가 있지만 Preview 및 후보 선택 UI가 연결되어 있지 않고 `Main.cpp`의 진입점은 진단 스크립트에 있다. 따라서 acceptance 문서의 “Preview를 누른다”, “후보 셋 중 고른다”는 일반 사용자 경로가 마련된 뒤 수행해야 한다. 사람의 청음이 필요한 것과 UI가 아직 없는 것을 구분해 기록할 필요가 있다.
