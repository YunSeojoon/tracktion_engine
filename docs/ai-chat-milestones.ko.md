# CoCompose — 선택 영역 기반 AI 공동 작곡 마일스톤

2026-09-11. 계획 작성 시 로컬 HEAD 72e36f3. 이 문서는 새 제품 요구사항이며 구현 완료 보고가 아니다. 기존 RC의 안정화와 사람의 청음/실장치 검증은 계속 유효하다. 과거의 '내부 채팅 후순위'를 이번 사용자 요청으로 구체화한다. laplas 연동은 보류한다.

## 목표

DAW에서 작업 대상을 선택하고 대화에 첨부한다. AI는 무엇을 보고 무엇을 바꿀 수 있는지 구분하며, 사용자는 제안을 확인·미리듣기·채택하고 한 번에 되돌린다. 열린 프로젝트와 재생을 유지한다. 단순 채팅창이나 파일 전체를 무조건 보내는 기능으로 완료하지 않는다.

대표 시나리오:

| 선택 | 질문/요청 | 기대 동작 |
|---|---|---|
| Playlist 9~16마디와 Bass/Drums | 여기 전개가 이상해 | 선택과 앞뒤 문맥을 읽고 근거 있는 진단. 요청 전에는 수정하지 않음 |
| Mixer Insert 5 | 여기 꽂힌 플러그인 좀 봐줘 | 효과 순서·공개 파라미터·라우팅을 설명. 읽지 못하는 내부 상태는 모른다고 표시 |
| 피아노롤 일부 노트 | 리듬은 유지하고 이것 좀 다시 찍어봐 | 선택 노트의 음정 변경안. 리듬/다른 노트 보존, 원본과 비교 후 적용 |
| 킥·베이스와 4마디 | 저음이 부딪히는 것 같아 | MIDI/믹서 구조와 선택적 오디오를 구분해서 분석; 실제 오디오 미전송 시 들었다고 표현하지 않음 |

## 확정할 동작 원칙

- 선택은 첨부 시 고정된다. 사용자가 나중에 다른 곳을 클릭해도 전송 대상이 몰래 바뀌지 않는다. '현재 선택으로 갱신'은 명시적 동작이다.
- 첨부 카드는 `9–16마디 · Bass/Drums`, `Insert 5 · FX 4개`, `Lead · 노트 12개`처럼 표시한다. 클릭하면 위치로 이동, 제거/범위 갱신/전송 내용 확인 가능. 삭제된 대상은 찾을 수 없음으로 표시한다.
- 읽기 문맥과 수정 권한은 별개다. 앞뒤 구간과 관련 채널을 읽어도 선택 밖을 고치지 않는다. 기본은 묻기/분석이며, 수정 요청에는 제안서를 만든다. 최초 버전은 자동 적용하지 않는다.
- 피아노롤의 패턴은 여러 클립에서 재사용될 수 있다. '패턴 전체를 바꿔 N개 배치에 반영'과 '이 배치만 독립 복제 후 수정'을 요청 전에 선택하도록 한다. 기본값은 선택 배치만 수정이다. 패턴 자체를 선택했으면 모든 참조 영향 수를 표시한다.
- 채팅/패널 이동/진행률은 음악 revision이나 Undo를 오염시키지 않는다. 대상 음악 변경만 충돌 판단에 사용한다.
- 외부 AI 파일 연동은 유지한다. 내부 채팅도 기존 모델 검증·음악 편집 경로를 재사용한다. 제안서를 검증된 편집으로 변환하며 모델 출력을 임의 C++/Python 코드로 실행하지 않는다.
- 채팅 패널은 기존 패널과 동일한 resize와 `— □ ×` 최소화/최대화/닫기를 지원한다. 닫기는 대화 삭제나 요청 취소가 아니다. 취소 버튼은 별도로 둔다.

## 구현 계약

### 프로젝트 단위 대화 세션 — 사용자 확정

질문마다 새 대화를 생성하지 않는다. 프로젝트의 영구 project_id에 연결된 conversation_id로 메시지·첨부·제안·채택 이력·작업 메모를 이어간다. 앱 재실행 후에도 복원한다. 실행 때마다 달라지는 라이브 싱크 session_id는 충돌 방지용 실행 식별자이며 대화 식별자로 사용하지 않는다.

- 새 질문은 같은 대화에 추가한다. provider conversation/thread 기능이 있으면 연결을 유지하고, 없으면 로컬 기록과 검증된 요약으로 연속성을 제공한다. 네트워크 연결을 계속 열어두는 것이 세션 유지의 조건은 아니다.
- 프로젝트를 바꾸면 그 프로젝트 대화로 전환한다. 늦게 도착한 응답은 원래 프로젝트에만 기록하고 현재 열린 다른 프로젝트에 적용하지 않는다.
- 대화는 명시적인 '새 대화'로만 분기한다. 이전 대화는 보관한다. 패널 닫기/최소화, 모델 교체, 인증 갱신, 일시적 네트워크 실패로 대화를 초기화하지 않는다.
- 다시 열 때 현재 live session/revision을 새로 조회한다. 대화는 이어져도 이전 실행의 수정 제안을 그대로 재적용하지 않으며 만료/재검증 대상으로 표시한다.
- 프로젝트 폴더 이름이나 경로 변경은 같은 project_id로 인식한다. '다른 이름으로 저장/프로젝트 복제'에는 새 project_id를 부여하고, 작업 메모 복사와 대화 이력 참조 여부를 명시한다. 원본과 복제본이 하나의 수정 세션을 공유하면 안 된다.
- 문맥 한도에 가까워지면 과거 메시지를 요약하되 원문은 로컬에 유지한다. 확정 조건·현재 선택·진행 중 제안은 누락하지 않는다. 요약을 새로운 사용자 지시로 승격하지 않는다.

### 작업 메모·의도·후보

프로젝트 작업 메모를 (1) 사용자가 확정한 조건, (2) AI 추정, (3) 현재 요청으로 나눈다. 확정 조건은 사용자가 직접 지정/수정하거나 AI의 제안을 확인한 경우만 등록한다. AI 추정에는 출처·대상 revision·확실하지 않음을 표시한다. 음악이 바뀌면 관련 조성/구조 추정은 재검토 대상으로 둔다.

변형 강도는 '살짝 다듬기/적극 변형/새로 만들기'를 제공하되 강도와 수정 권한을 혼동하지 않는다. 음정·리듬·velocity·길이·악기 등 보존 조건을 함께 표시하고 validator가 강제한다. 강도를 높여도 잠금과 선택 범위는 유지한다.

'여기 이상해'처럼 대상은 있지만 목표가 모호하면 리듬/화성/음색 등 구체적 질문을 한다. 이미 명확한 요청에 매번 확인을 요구하지 않는다. 질문 중에도 선택 첨부와 원래 요청을 유지한다.

구간 마커/할 일에는 stable ID, beat 범위, 대상 트랙/클립, 메모, 연결 대화를 저장한다. 클립에 붙인 메모는 클립 이동을 따르고, 시간에 붙인 메모는 시간을 유지한다. 대상 삭제 시 연결 끊김을 표시하며 다른 대상으로 임의 이동하지 않는다.

후보 보관함은 원본·대안·채택/기각 상태·기준 revision·미리듣기 자산을 묶는다. 보관한 후보는 자동 적용되지 않으며 오래된 후보는 현재 곡과 다시 비교한다. 후보 삭제는 채택된 음악을 삭제하지 않는다.

모델 교체 시 확정 조건·선택 문맥·채택 변경·진행 중 요청을 새 모델에 전달한다. provider 고유 thread ID 대신 로컬 프로젝트 대화를 기준으로 한다. 지원하지 않는 오디오/도구 기능은 capabilities로 표시하고 새 모델이 이전 모델의 추정을 확정 사실로 받아들이지 않게 구분한다.

### 문맥 패킷

버전, project/session ID, base revision, attachment ID, 선택 타입, stable 대상 ID, 시간 범위, 스냅샷 및 수정 허용 범위를 포함한다. 내부 시간은 beat와 tempo map을 사용하고 화면에는 마디/박자로 변환한다. 음악 변화와 장치/패널 상태를 분리한다.

| 타입 | 필수 정보 | 추가 문맥 |
|---|---|---|
| 구간 | 레인/클립/채널 ID, 시작/끝 beat, 패턴 참조, 노트/자동화 | 앞뒤 기본 1마디(조절 가능), tempo/박자, 관련 라우팅 |
| 노트 | 패턴/시퀀스/노트 ID, pitch/start/length/velocity | 악기, 다른 성부, 재사용 배치 수 |
| Insert | stable insert ID + 현재 번호, 효과 순서/ID/형식/bypass/wet-dry/공개 파라미터, output/send | 관련 입력 채널, 선택 범위의 미터/렌더 |
| 오디오 | 자산 ID/해시, 클립 offset/길이/gain/fade/stretch | 사용자가 선택한 범위의 오디오 파일 |

사용자 이름/파일명은 표시용이며 식별자는 stable ID다. 경계를 걸치는 노트는 읽을 수 있지만 수정 범위 정책을 명시한다. 최초에는 선택 밖까지 걸친 노트 수정은 막거나 사용자가 범위를 확장하도록 한다. 긴 프로젝트/대량 파라미터는 요약과 필요한 항목 조회로 나누고 잘린 문맥은 표시한다. 전체 VST 바이너리/라이브러리/인증 정보는 보내지 않는다.

### 수정 제안

proposal ID, request ID, base revision, 첨부 스냅샷 식별자, 읽은 의존 대상, write scope, 변경 전후 값, 설명을 보관한다. 기존 전체 스냅샷 프로토콜을 처음부터 폐기하지 않는다. 검증된 제안을 최신 프로젝트에 적용하는 경계에서 선택 밖 변경을 차단한다.

노트/클립/파라미터/라우팅별 diff를 보여준다. 요청 상태는 준비→문맥 수집→전송→응답→제안 준비→미리듣기→적용/거절/만료로 구분한다. 요청 취소·실패·재시도는 음악을 바꾸지 않는다. 동일 proposal 중복 적용을 막는다.

### 연결과 대화 저장

첫 버전은 단일 provider 또는 로컬 외부 agent bridge 하나만 실제로 연결한다. 설정 화면은 지원하는 인증 방식·텍스트/오디오 기능을 정확히 표시한다. ChatGPT 웹 로그인/구독이 앱 API 인증과 같다고 가정하지 않는다. 특정 SDK/모델 선택은 구현 시 공식 문서로 확인한다.

키는 OS 자격 증명 저장소 등에 보관하며 프로젝트·대화 export·로그에 넣지 않는다. 사용자가 선택한 연결로 보내기 전에 카드로 전송 범위를 알 수 있어야 한다. 일반 전송마다 중복 확인 창을 띄우지 않는다. 오디오는 기본 미첨부, 별도 토글로 켠다. 대화는 로컬 프로젝트에 연결하되 곡 저장과 별도 파일로 보존하고 삭제/export를 제공한다. 스트리밍 응답 도중 종료해도 불완전 제안은 적용하지 않는다.

## 마일스톤

### A0. 패널과 선택 문맥 기반

패널 최대화/복원 요구부터 충족한다. Playlist/피아노롤/Insert 선택을 공통 첨부 객체로 변환하고 우클릭 'AI에게 물어보기', 채팅으로 드래그, 충돌 없는 단축키를 같은 경로로 연결한다. attach 직후 선택은 고정된다. 실제 외부 전송 없이 문맥 inspector로 확인 가능하게 한다.

완료: 세 종류 선택의 카드·범위·ID가 정확하고 위치 이동/제거/갱신이 동작한다. 패널 최대화 중에도 선택 첨부 가능. 음악 revision이 UI 동작으로 증가하지 않는다. 동명 채널, tempo 변경, 패턴 재사용, 삭제 대상 사례 포함.

### A0.5. 모델 공통 DAW 명세·도구 계약

[ai-daw-tool-contract.ko.md](ai-daw-tool-contract.ko.md)를 구현 기준으로 한다. 단위·stable ID·패턴 공유·수정 범위·오류 계약을 문서와 기계 판독 스키마로 제공한다. capabilities 조회와 공통 읽기/제안/적용 서비스에 내부 채팅·외부 CLI를 연결한다. 독립 편집 스크립트를 복제하지 않고 공통 도구를 조합하는 초기 레시피를 제공한다.

완료: 스키마를 통과하는 실제 예제, 잘못된 범위/단위/충돌 거절, 중복 적용 방지, 동일 요청에 대한 채팅/CLI 경로의 동등성 검사. 읽기 도구부터 A1에 제공하고 쓰기 도구는 A2에서 구현 완료한다. 장래 도구를 이미 실행 가능한 것처럼 노출하지 않는다.

### A1. 실제 내부 채팅 — 읽기 전용 진단

프로젝트 대화 세션 생성·계속 사용·로컬 저장·재실행 복원을 이 단계에서 구현한다. 같은 프로젝트에 두 번 질문했을 때 두 번째가 앞선 질문/답변/첨부를 참조해야 한다. 대화 연속성을 A4까지 미루지 않는다.

연결 하나를 끝까지 구현한다. 비동기 전송/스트리밍/중단/재시도/인증·제한·네트워크 오류를 처리하고 입력 중인 글을 보존한다. 첨부 내용을 사람이 이해하는 형태로 보여준다. 분석 답변은 대상 링크를 포함한다. 응답에 담긴 수정 의도는 아직 실행하지 않는다.

완료: 실제 provider/bridge를 통해 '구간 이상함', 'Insert 플러그인 확인', '노트 설명' 세 질문에 첨부 대상과 연결된 응답을 받는다. 오디오를 안 보냈으면 청음 주장 없음. 요청 중 UI/재생 유지. 테스트 응답만으로 연결 완료라 하지 않는다.

### A2. 선택 범위 수정 제안과 원자적 적용 — 첫 실사용 MVP

초기 쓰기 범위는 MIDI 노트 추가/삭제/pitch/start/length/velocity와 기존 플러그인의 공개 파라미터로 제한한다. 효과 추가/삭제, 복잡한 라우팅 변경은 A5로 넘긴다. 변경 노트를 고스트 표시하고 원본과 구분한다. '음정만/리듬만/velocity만' 보존 조건과 트랙/구간 잠금을 검증한다.

제안 생성 중 대상 또는 읽은 의존 데이터가 달라졌으면 stale 표시하고 재생성을 요청한다. 초기에는 보수적인 revision 거절을 사용해도 된다. 무조건 최신 전체 스냅샷을 덮어쓰는 자동 재시도는 금지한다. 오류는 부분 적용 없이 종료한다.

완료: '리듬 유지하고 다시 찍기'에서 선택 밖과 리듬은 그대로, 요청한 음정만 변경. 한 번 적용=Undo 한 번, Redo 복원. 잘못된 ID/범위/잠금 침범 거절. 중복 클릭 중복 적용 없음. 사람이 중간에 수정한 내용 보존. 패턴 공유 영향이 설명과 일치한다.

### A3. 오디오 문맥과 A/B 미리듣기

현재 렌더 기반을 재사용해 선택 구간 원본/제안을 별도 스냅샷에서 렌더한다. 결과는 source revision·구간·렌더 설정·오디오 해시로 구분한다. A/B는 같은 시작 위치/길이/공통 믹스 경로를 사용하며 effect tail과 앞구간 pre-roll 정책을 기록한다. 레벨 매칭은 선택 사항으로 명시하고 export 오디오를 몰래 정규화하지 않는다.

오디오 지원 연결에서만 실제 파일을 첨부한다. 원음/제안/전체 mix/선택 solo 중 무엇을 보내고 듣는지 표시한다. 지원하지 않으면 구조 분석만 제공한다. 프리뷰 출력은 원 프로젝트의 클립·VST 상태를 바꾸지 않는다.

완료: 원본/A/B 전환 후 원 프로젝트 불변. 렌더 실패/취소 시 기존 파일 보존. 수정 후 오래된 프리뷰 구분. 실제 음색을 고른 VST에서 소리가 들리고 사람이 비교 가능. 파일 생성만으로 'AI가 들음' 완료 처리 금지.

### A4. 반복 대화·추적·충돌 UX

A1의 영속 대화 위에 프로젝트 작업 메모, 변형 강도/보존 조건, 의도 확인, 구간 마커·할 일, 후보 보관함, 모델 교체 인계 기능을 추가한다. 작업 메모 편집·후보 관리 등 대화 메타데이터는 음악 Undo/revision과 분리한다. 실제 구간 마커를 곡 데이터에 저장하는 경우에는 그 명령의 음악 상태 변경 여부를 명세하고 일관되게 처리한다.

추가 완료 검사: 프로젝트 A/B를 오가도 대화가 섞이지 않음, 앱 재실행 후 A 대화/확정 조건 복원, 늦은 응답은 A에만 귀속, 모델 교체 후 같은 요청/보존 조건 유지, 새 대화 분기 후 과거 이력 열람, 프로젝트 복제 후 독립 제안 적용. AI 추정을 확정 조건으로 자동 등록하지 않음. 높은 변형 강도에서도 잠금/리듬 보존을 위반하는 제안 거절. 클립 이동/삭제 시 연결 메모의 의미 보존.

'방금 것보다 덜 복잡하게'를 이전 proposal과 연결한다. 대안은 원본을 보존한 버전으로 쌓으며 채택한 것/기각한 것을 구분한다. 적용 위치 강조와 클릭 이동, 대화 복원/export/삭제를 제공한다. 오래된 제안의 세부 충돌을 보여주고 원하면 최신 선택으로 다시 요청한다.

완료: 3회 수정 대화에서 참조 대상과 채택 이력 명확. 재실행 후 적용済 제안을 중복 적용하지 않음. 프로젝트 전환 때 다른 프로젝트 결과가 섞이지 않음. 채팅을 닫거나 최소화해도 편집 상태 유지. 개별 hunk 선택 적용은 의존성이 있을 때 보류하고 첫 버전은 제안 단위 적용을 유지한다.

### A5. 편곡·믹서 협업 확장

트랙/클립 생성·배치 이동, 효과 체인 변경·send/bus 수정으로 쓰기 범위를 확장한다. 플러그인 추가는 설치된 목록의 유효 ID만 사용한다. 없는 플러그인은 자동 설치하지 않고 사용자에게 대안을 보여준다. routing cycle, gain 범위, shared bus 영향, 자동화 대상 소실을 검증한다.

완료: 'Insert 5 정리' 제안이 플러그인 순서와 연결 변화까지 설명하고 A/B/Undo 가능. 실패한 VST 생성은 기존 체인을 보존. 여러 채널에 미치는 영향 표시. 새 효과는 임의 기본값이 원치 않는 큰 소리를 내지 않도록 적용 전 미리듣기로 확인.

### A6. AI 공동 작곡 수용 검사와 배포

같은 빌드에서 세 대표 시나리오를 실제 마우스/키보드와 실제 AI 연결로 검사한다. 단위/통합 검사는 고정 응답으로 검증 경계를 재현하고, 실제 모델 평가는 특정 문장 일치 대신 범위 준수·보존 조건·음악적 결과를 평가한다. 네트워크 단절/취소/느린 응답/인증 실패/긴 문맥/동시 외부 수정도 포함한다.

완료: '구간 진단→피아노롤 재작성→Insert 검토→A/B→적용→Undo'를 한 세션에서 재열기 없이 수행. 요청/렌더 시간과 UI 응답성을 기록. 키/불필요한 로컬 경로가 로그나 배포물에 없음. 모델 오류가 프로젝트 손상으로 이어지지 않음. 사람이 청음한 결과와 미검증 항목을 별도 기록.

## 순서와 범위 관리

기본 DAW 마우스/키보드 동작은 [daw-interaction-spec.ko.md](daw-interaction-spec.ko.md)의 D0~D4를 따른다. A0의 구간 선택·우클릭 첨부는 D0/D1과 함께 구현한다. 룰러 seek/시간 선택/루프와 우클릭 메뉴 의미를 먼저 통일해 채팅 선택 계약과 충돌하지 않게 한다.

A0 → A0.5 → A1 → A2가 첫 실사용 MVP. A3 → A4로 공동 작곡 루프를 완성하고 A5는 그 뒤 확장한다. A6 검사는 각 단계에서 누적한다. 이전 P0/P1 안정화 경계를 퇴행시키지 않는다. 패널 자유 도킹·멀티모니터 분리, 자율 무승인 편집, 여러 AI 동시 편집, 음성 대화, laplas는 이번 필수 범위가 아니다.

## Claude 전달용

이 문서를 새 AI 기능 요구사항으로 읽고 기존 RC 상태를 먼저 확인해줘. A0부터 구현하고 범위/ID/패턴 공유 문맥 검사를 남겨. 내부 채팅도 기존 모델 검증과 Undo를 재사용하고 외부 파일 연동을 유지해. A1에서 실제 연결 하나를 검증한 뒤 A2의 선택 범위 제안/적용으로 진행해. API 키를 대화/프로젝트에 저장하지 말고, 선택 이후 사용자의 편집을 오래된 AI 응답으로 덮어쓰지 마. 각 마일스톤에 실행 방법·검사 결과·미검증 항목을 남겨줘.
