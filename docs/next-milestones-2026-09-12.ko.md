# 다음 마일스톤 — 실제 공동 작곡 베타

2026-09-12. 계획 기준 HEAD ba6fc2f와 작업 기록. 제안 경계 수정은 작업 트리에 있으며 이번 계획 작성에서 새 빌드 검증은 하지 않았다. 기존 A/D 문서는 상세 사양으로 유지하고, 이 문서는 다음 작업의 순서와 완료 판정을 정한다. 과거 리뷰 문서의 시작 커밋으로 돌아가지 않는다.

## 이번 목표

사용자가 앱을 열어 직접 편곡하다가 구간/노트/Insert를 AI에게 보내고, 제안을 듣고 적용·Undo한 뒤 다음 날 같은 프로젝트 대화를 이어갈 수 있는 베타. 기능 개수보다 이 한 작업 흐름의 완결을 우선한다.

## B0. 제안 경계 수정 검증 및 기준 빌드 고정

현재 미커밋 수정을 보존해 읽고 review-v4와 dynamic-review 문서의 R1~R3을 수정본에서 재검사한다. test_proposal_boundaries.py에서 질문 후 수동 편집, Insert-only 노트 변경, 추가 노트 기본값/타입/알 수 없는 명령을 검사한다. 실제 응답 수신→제안→Apply 경로가 포함돼야 한다.

완료 조건:
- 오래된 응답은 STALE_REVISION, 권한 없는 노트 제안은 OUT_OF_SCOPE 또는 명시적 유효성 오류로 거절되고 곡은 보존된다.
- add 기본값이 검증·diff·적용에서 일치하고 패턴 밖으로 나가지 않는다.
- 같은 EXE 해시로 도구/채팅/신뢰성/DAW 조작/라이브 싱크 회귀 결과를 남긴다.
- 테스트는 앱 단일 인스턴스를 독점하는 한 실행기에서 순차 실행한다. 다른 앱 점유는 사전 진단으로 중단하며 검사 실패와 구분한다. 실행 중 다른 개발이 빌드하지 않도록 기준 소스/EXE를 고정한다.

이 단계는 새 기능보다 먼저다. 기존 정상 사례의 통과가 경계 문제 해결 증거를 대신하지 않는다.

## B1. 모든 주요 대상에서 자연스러운 DAW 조작

기존 D0~D4 구현을 재사용하고 남은 레인/채널 헤더, Insert/FX 슬롯, 오디오 클립, 노브/페이더 우클릭 메뉴를 완성한다. 피아노롤/오디오 편집기 진입, 수치 입력, 선택/Draw, 이동/trim/stretch 모드, 줌/스크롤, 패널 — □ ×/복원을 하나의 규칙으로 점검한다.

완료 조건: 실제 마우스·키보드로 샘플 드롭→패턴 작성→클립 더블클릭 편집→편곡→FX 열기→자동화 수정→AI 첨부를 수행한다. 메뉴를 여는 것만으로 음악이 변하지 않는다. 채팅/텍스트 입력 중 Space/Delete/Enter/Home이 DAW 명령을 오작동시키지 않는다. 스크립트 검사가 못 만든 포커스 상태는 실제 조작으로 확인하고 기록한다.

## B2. 들은 제안과 적용 결과 일치

현재 노트 중심 A/B를 기존 파라미터 변경까지 확장한다. 노트+파라미터 혼합 제안에서 노트만 미리듣고 전체를 Apply하는 불일치를 없앤다. 구현하지 못한 변경 유형은 '전체 미리듣기 불가'를 명확히 표시하고 부분 프리뷰를 완전한 결과처럼 제시하지 않는다.

원본/제안은 동일 범위·시작 위치·pre-roll/tail·기준 revision으로 렌더한다. 변형한 VST opaque state도 스냅샷에서 일관되게 유지한다. 렌더 도중 편집해도 활성 곡은 유지하며 오래된 preview에는 표시를 붙인다. 선택 배치만 수정과 공유 패턴 전체 수정의 영향도 preview/Apply에서 같아야 한다.

완료 조건: 노트/파라미터/혼합 세 종류의 A/B→Apply→다시 렌더를 비교한다. 비결정적 신스는 파일 해시 동일성 대신 설정/범위/허용 오차와 청음으로 평가한다. 실제 사람이 재생과 파일을 듣고 판단한 기록을 남긴다. 미지원 plugin은 제한으로 기록한다.

## B3. 반복 작곡과 후보 보관함

프로젝트별 대화와 확정 조건/AI 추정/현재 요청 메모를 기반으로 변형 강도(살짝/적극/새로)와 음정·리듬·velocity 보존 조건을 제공한다. 사용자 확정 조건을 실제 validator가 지키게 한다. 자연어 지시가 애매하면 확인하되 명확한 요청에는 반복 확인하지 않는다.

후보는 원본·대안·채택 여부·기준 revision·프리뷰를 보존한다. '방금 것보다 덜 복잡하게'가 정확한 후보를 참조해야 한다. 구간 메모/할 일은 시간 고정 또는 클립 추적을 구분하고 이동/삭제 후 연결을 보존하거나 끊김을 표시한다.

완료 조건: 같은 부분의 후보 3개 생성→청음→두 번째 채택→Undo→재실행→후보/대화 복원. 기각 후보 삭제가 채택 음악을 삭제하지 않는다. 높은 변형 강도도 scope/잠금/보존 조건을 넓히지 않는다. stale 후보는 최신 상태에 몰래 덮어쓰지 않는다.

## B4. 모델 교체와 사용자용 연결 흐름

현재 검증된 로컬 ollama를 기준으로 사용자가 연결 상태·모델·지원 기능을 앱에서 확인하도록 한다. CLI만 아는 개발자가 아닌 사용자도 실행 가이드를 따라 연결/재연결할 수 있어야 한다. hosted provider는 사용자가 선택/인증한 경우 별도 검증하고 실제 API 성공과 로컬 성공을 구분한다.

모델 교체는 로컬 conversation_id와 프로젝트 작업 메모를 유지한다. 진행 중 요청은 취소/완료 처리한 뒤 명시적으로 전환한다. 늦은 응답은 원래 요청에 귀속하고 다른 모델의 답으로 표시하지 않는다. 각 연결의 오디오/도구 기능을 capabilities와 UI에 일치시킨다.

완료 조건: 모델 변경 후 이전 선택·확정 조건·채택 이력으로 후속 질문 가능. 네트워크 단절/bridge 재시작/잘못된 인증에서 입력 글과 곡 보존. 키가 프로젝트/대화/배포 로그에 없음. 두 모델 검증이 없으면 모델 독립 계약 구현과 실제 교체 검증을 구분해 보고.

## B5. 편곡·믹서 쓰기 범위 확장 (A5)

기존 노트/파라미터 경계가 안정된 뒤 클립 이동·복제, 선택 배치 Make unique, 효과 추가/순서/제거, send 변경을 단계적으로 공개한다. 설치된 플러그인 ID만 사용하고 graph cycle/자동화 참조/다른 채널 영향/실패 rollback을 검사한다. 각 종류는 preview까지 지원한 후 capabilities에 공개한다.

완료 조건: '후렴 드럼 변형'과 '이 Insert 체인 정리'의 범위·영향·diff·preview·Apply·Undo가 일치한다. 지원하지 않는 요청은 설명하고 거절한다. 자동 plugin 설치나 사용자 범위를 넘어선 임의 믹스 수정은 하지 않는다.

## B6. 사람과 함께하는 베타 수용 검사

16줄 수용 검사 기록의 현재 상태를 최신 빌드에 맞춰 갱신한다. 실제 VST 음색 선택, MIDI/오디오 녹음, 장치 전환, 곡 저장/복원, 채팅 포커스, A/B 청음, 100/150/200% 실제 화면 가독성을 사용자와 확인한다. 무음 plugin의 원인을 라이브러리 탓으로 가정하지 않는다.

완료 조건: 한 곡에서 '구간 진단→노트 재작성→Insert 확인/수정→A/B→채택→Undo→다음 날 대화 재개'를 완료한다. 검사 EXE/프로젝트/기기/모델/설정/실제 결과를 연결한 베타 보고서를 남긴다. 수동 CI 정책을 유지하고 배포 시 명시적으로 gate를 실행한다. 미해결 P1이 있으면 새 릴리스 후보로 올리지 않는다.

## 순서와 범위

B0 → B1 → B2 → B3 → B4 → B5 → B6. B6의 사람 검사 준비는 B1부터 진행하며 마지막에 한꺼번에 몰지 않는다. B4 UI 정리는 B2 이후 독립적으로 가능하다. B5는 큰 확장이므로 우선 B0~B4를 내부 베타로 사용할 수 있다.

보류: laplas, 클립 런처/Session View, 여러 AI의 동시 자율 편집, 음성 채팅, DAW마다 별도 입력 모드, 전체 plugin ecosystem 복제. 기존 FL/Cubase/Ableton 참고 사양은 daw-interaction-spec.ko.md를 따른다.

이 문서 기준 최신 소스와 미커밋 변경을 확인하고 B0부터 완료해줘. 과거 리뷰 EXE와 현재 수정본을 구분하고 실제 경계 회귀 결과를 남겨. 테스트 앱 동시 실행을 피하고 한 빌드에서 검사를 순차 수행해. 다음은 B1 남은 메뉴/포커스와 B2 전체 제안 A/B를 우선해. 새 기능마다 기존 프로젝트 대화·라이브 싱크·scope·Undo를 유지하고, 코드 구현과 실제 모델/청음 검증을 따로 기록해.
