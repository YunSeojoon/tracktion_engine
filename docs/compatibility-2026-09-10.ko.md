# CoCompose 실제 환경 호환성 표

작성일: 2026-09-10
대상: `docs/review-next-milestones-2026-09-10.ko.md`의 N4

이 문서는 이 기계에 실제로 설치된 VST3와 실제 오디오 인터페이스로 앱을 돌린 결과다. 표의 모든 칸은 이번에 측정한 값이며, 측정하지 못한 항목은 빈칸이 아니라 미검증으로 적었다.

## 재현 절차

두 개의 스크립트가 이 표를 만든다. 둘 다 앱을 실제로 띄우고 UI 스크립트와 `project.json`으로 조작하며, 결과는 `state.json`과 렌더된 WAV에서 읽는다.

```
python tools/test_plugin_compatibility.py --output <폴더>
python tools/test_real_environment.py --output <폴더> --minutes 65
```

`test_plugin_compatibility.py`는 스캔을 먼저 돌린 뒤 악기마다 다음을 수행한다.

1. 네 마디짜리 패턴을 만들어 편곡에 놓는다.
2. 채널의 악기를 그 플러그인으로 바꾸고, 엔진 트랙에 실제로 올라왔는지와 파라미터 수를 읽는다.
3. 플러그인 자신의 창을 띄우고 엔진에 창이 떠 있는지 묻는다.
4. 첫 파라미터에 자동화 점 두 개를 찍고 엔진 곡선에 두 점이 들어갔는지 확인한다.
5. 믹스를 WAV로 렌더하고 peak를 잰다.
6. 앱을 닫고 다시 열어 플러그인과 자동화가 돌아왔는지 확인한다.

효과는 채널이 지나는 인서트에 얹고, 얹기 전 렌더 peak(전)와 얹은 뒤 peak(후)를 함께 적는다. 바이패스가 엔진까지 닿는지도 확인한다.

## 스캔

기본 VST3 경로에서 파일 24개를 읽어 플러그인 23개를 찾았다. 악기 12개, 효과 11개다. 스캔은 한 틱에 파일 하나씩 처리하므로 앱이 살아 있는 채로 진행되고, 앱을 죽이는 플러그인은 dead man's pedal 파일에 이름을 남겨 다음 실행에서 건너뛴다. 이 기계에서는 앱을 죽인 플러그인이 없었다.

## 장치·화면·장시간

| 검사 | 결과 |
|---|---|
| 오디오 장치 열림 | Windows Audio, 48000 Hz, 버퍼 480, 32 bit |
| 재생 / 정지 | O / O (재생 위치가 실제로 움직임) |
| 반복 저장·Undo | 25회. 패턴 수 2 → 2, 되돌아옴 |
| 연속 재생 | 65분, 195회 확인 모두 재생 중, 앱 살아 있음, 멈춤 없음 |
| 100% 배율 | 창 1420x860, 패널 19개 |
| 150% 배율 | 창 1420x860, 패널 19개 |
| 200% 배율 | 창 1272x656, 패널 19개 |

연속 재생은 Song mode로 편곡 전체를 반복시키고 65분 동안 20초마다 상태를 읽었다. 195번 모두 재생 중이었고 위치가 계속 돌았다. 그동안 revision은 57에서 움직이지 않았다. 재생만으로는 프로젝트가 변한 것으로 취급되지 않는다는 뜻이고, 자동 백업도 마지막 편집 이후 더 쌓이지 않았다.

배율 표의 창 크기는 창 자신의 단위다. 배율이 곱해지므로 숫자가 커지지 않는 것이 정상이고, 확인해야 할 것은 창이 화면에 들어가면서 패널이 모두 남아 있는지다. 세 배율 모두 19개 패널이 그대로다.

## 청음

3채널(베이스·코드·리드) 16초 곡을 만들어 렌더했다. 리드는 Vital, 채널 인서트에 ValhallaSupermassive를 얹었다. 결과는 peak 0.2023, RMS 0.045로 무음도 클리핑도 아니다. 파일은 사용자에게 전달했고 실제로 어떻게 들리는지는 사람이 판단한다. 이 항목은 그 판단이 오기 전까지 미검증이다.

## 발견한 버그

### B1 [P1] VST3 악기가 sync마다 다시 만들어져 자동화가 끊긴다 — 고침

모델은 `KnownPluginList`가 주는 식별자를 저장하는데, 이미 올라온 플러그인을 알아볼 때는 엔진의 `ExternalPlugin::getIdentifierString()`을 썼다. 이쪽은 2021년 이전 형식이라 두 문자열이 절대 같아지지 않았고, `syncInstrument`는 매 sync마다 플러그인을 지우고 다시 만들었다. 새로 만들어진 플러그인은 새 `itemID`를 받으므로 자동화 곡선이 가리키던 플러그인이 사라졌다. `state.json`에서 `parameter_found: false`, `engine_points: 0`으로 나타났다.

같은 문자열로 비교하도록 고쳤다. 그런데 그것만으로는 부족했다. 엔진은 플러그인 인스턴스가 뜨고 나면 `desc = pi->getPluginDescription()`으로 설명을 인스턴스가 보고한 값으로 덮어쓴다(`tracktion_ExternalPlugin.cpp:1200`). 일부 플러그인은 이때 스캔 목록과 다른 값을 보고하므로 설명으로 비교하는 방법 자체가 믿을 수 없다. 그래서 만들 때 모델이 요청한 문자열을 플러그인 상태에 `coComposeRequest`로 적어두고 그것으로 비교한다.

재현: 채널 악기를 MODO BASS 2 / SINE Player / Splice INSTRUMENT 중 하나로 바꾸고 파라미터에 자동화 점을 찍은 뒤 `state.json`의 `automation.curves[0].engine_points`를 본다. 고치기 전 0, 고친 뒤 2.

### B2 [P1] 150%/200% DPI에서 창이 화면보다 커진다 — 고침

창을 항상 1420x860으로 열고 최소 크기를 1180x620으로 고정했다. 이 값은 창 자신의 단위라 배율이 곱해지므로 200%에서는 실제로 2840x1720이 되고, 최소 크기마저 화면보다 커서 줄일 수도 없었다. 두 값 모두 디스플레이가 실제로 내주는 크기로 제한한다. 이 기계(2560x1440)에서 100%와 150%는 1420x860 그대로, 200%는 1272x656으로 열리고 19개 패널이 모두 남는다.

### B3 [P2] 믹서가 내장 효과 6개만 제공했다 — 고침

스캔된 플러그인 중 악기가 아닌 것을 모두 인서트에 얹을 수 있게 했다. 이 기계의 효과 11개가 모두 올라오고 파라미터를 보고하며 바이패스가 엔진까지 닿고 재시작 후 돌아온다. 설치되지 않은 플러그인을 요구하는 프로젝트는 그 칸만 비고 문서 전체가 거절되지는 않는다.

### B4 [P2] 두 번째 프로젝트를 열면 아무 일도 일어나지 않았다 — 고침

`moreThanOneInstanceAllowed()`가 false인데 `anotherInstanceStarted`를 받지 않아, 이미 앱이 떠 있는 상태에서 다른 프로젝트를 열면 두 번째 프로세스가 조용히 사라졌다. 실행이 실패한 것처럼 보인다. 이제 떠 있는 창을 앞으로 가져오고 어떤 프로젝트를 이미 열고 있는지 알린다. 한 번에 한 프로젝트라는 제약 자체는 유지한다. 앱이 그 폴더의 live sync 파일을 소유하기 때문이다.

### B5 [P3] 소리를 내지 않는 악기가 있다 — 버그 아님

렌더 peak가 0인 악기가 여럿이다. Kontakt 8, SINE Player, sforzando, Ample 4종, VOCALOID VSTi는 모두 자기 라이브러리나 음원을 따로 불러와야 소리가 나는 종류다. 앱은 플러그인을 올리고 MIDI를 보내고 파라미터를 읽는 데까지 성공하며, 그 다음은 플러그인 자신의 창에서 사람이 음색을 고르는 일이다. 표의 peak 0은 실패가 아니라 "기본 상태에서는 무음"으로 읽어야 한다.

VOCALOID Bridge는 인서트에 얹으면 채널이 무음이 된다(전 0.111 → 후 0.0). 이 플러그인은 VOCALOID 편집기와 오디오를 주고받는 다리이지 일반 효과가 아니다.

## 미검증으로 남긴 것

- **청음.** 사람이 들어야 하는 항목이다. 이 문서와 함께 렌더한 WAV를 전달했고, 판단은 사용자의 몫으로 남긴다. 파형 상으로는 무음도 클리핑도 아니다.
- **장치 전환.** 재생 중에 Tools > Audio settings에서 다른 장치를 고르거나 USB 인터페이스를 뽑는 동작은 사람이 해야 확인된다. 검사는 어떤 장치가 열렸는지, 재생과 정지가 되는지까지만 다룬다.
- **다른 오디오 인터페이스.** 이 기계에 붙은 장치 하나로만 확인했다. ASIO 드라이버, 다른 샘플레이트나 버퍼는 미검증이다.
- **실제 MIDI 입력 녹음.** 건반이 붙어 있어야 확인된다.
- **VST2·AU.** VST3 기본 경로만 스캔한다.
- **플러그인 자체의 음색 설정.** 창이 뜨는 것까지만 확인하며, 창 안에서 음원을 고르는 일은 사람이 한다.
