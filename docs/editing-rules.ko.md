# 편집 조작 기본 규칙

편곡(Playlist)과 피아노롤에서 같은 손버릇이 같은 뜻인지, 어디서 갈라지는지를 한 장으로 모은 표다.
실행·설치·믹서·AI 사용법은 [windows-guide.ko.md](windows-guide.ko.md)에 있고, 여기는 **두 창의 조작
규칙만** 비교한다. 아래는 모두 소스에서 확인된 사실이다 — 근거는 `examples/CoCompose/PlaylistGrid.h`와
`examples/CoCompose/PianoRoll.h`다.

## 표

| 조작 | 편곡 (Playlist) | 피아노롤 |
|---|---|---|
| 대상 클릭 | 그것만 선택한다. 이미 선택 안에 있으면 선택을 유지한다 | 같다 |
| Shift+클릭 | 선택에 넣고 뺀다 | 같다 |
| 빈 곳 드래그 | 사각형 선택. Draw 도구일 때는 클립을 놓는다 | 사각형 선택. Draw 도구일 때는 노트를 만들고, **Alt를 누르면 만들지 않고 사각형 선택이 된다** |
| 우클릭 | 선택 안이면 선택을 유지하고, 밖이면 가리킨 것으로 선택을 옮긴다. 메뉴를 열거나 닫는 것만으로는 아무것도 바뀌지 않는다 | 같다 |
| 끌기 | 이동 (마디·레인) | 이동 (시간·음높이) |
| 오른쪽 끝 끌기 | 길이 조절 (끝에서 7픽셀) | 길이 조절 (끝에서 6픽셀) |
| 복제 | Ctrl+드래그, `Ctrl+D`, `Ctrl+R` | Ctrl+드래그, `Ctrl+D`. **`Ctrl+R`은 없다** |
| 스냅 임시 해제 | Alt를 누르고 있는 동안 | **없다** |
| Alt+드래그 | 스냅 해제 | velocity 변경 |
| 삭제 | `Delete` | `Delete` |
| 휠 | 세로 스크롤 / `Shift`+휠 가로 / `Ctrl`+휠 확대·축소(포인터 아래를 그대로 둔다) | 같다 |
| 자동화 행 | 눌러서 점을 만들고, 끌어서 옮기고, `Delete`로 지운다. **Ctrl 또는 Alt를 누른 채 두 점 사이를 끌면 곡선이 휜다** | 해당 없음 |
| 드래그 한 번 | Undo 한 번[^1] | Undo 한 번[^1] |

[^1]: 편곡 클립, 피아노롤 노트, 자동화 점, 믹서 페이더 네 자리에서 드래그 한 번이 Undo 여러 번이었고,
지금은 넷 다 한 번이다. 포인터를 한 번만 움직이는 검사에서는 드러나지 않던 결함이다.

## 어긋나는 곳은 둘이다

나머지 규칙은 두 창이 같다. 다른 것은 이 둘뿐이고, 둘 다 의도된 것이다.

- **`Ctrl+R`은 편곡에만 있다.** 선택한 클립을 바로 뒤에 반복하는 명령이라 배치가 있는 화면의 것이다.
  복제 자체는 두 창 모두 Ctrl+드래그와 `Ctrl+D`로 한다.
- **Alt의 뜻이 다르다.** 편곡에서는 스냅 임시 해제, 피아노롤에서는 velocity 드래그다. 편곡의 Alt는
  원래 사각형 선택이었고 그 일을 Select 도구가 맡으면서 비었으므로 스냅 해제를 받았다 — 대다수 편곡
  도구에서 Alt가 뜻하는 것과 같다. 피아노롤의 Alt=velocity는 오래된 조작이고, 그것을 바꾸는 것은
  **명세가 요구하지도 않는 일관성을 사려고 근육 기억을 깨는 일**이다. 두 창은 도구가 다른 별개의
  창이며, 어긋나는 자리는 조용히 맞추지 않고 적어 둔다. (`PlaylistGrid.h`의 `snapped()` 바로 위 주석)

## 아직 빈자리

**피아노롤에는 스냅을 임시로 푸는 길이 아예 없다.** `PianoRoll.h:186`에서 스냅이 조건 없이 걸린다.
편곡에 있는 탈출구가 여기에는 없다는 뜻이다.

이것은 결정이 아니라 미결이다. Alt는 이미 velocity가 쓰고 있으므로 탈출구를 준다면 다른 수식키여야
하고, 어떤 키로 할지는 정해지지 않았다. 같은 내용이
[workflow-gaps-2026-09-14.ko.md](workflow-gaps-2026-09-14.ko.md)에도 적혀 있다.
