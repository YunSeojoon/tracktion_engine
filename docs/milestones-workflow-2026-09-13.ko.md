상태: 사용자와 합의한 계획. 아래 체크 항목은 아직 완료 판정하지 않았다.

## 목표와 우선순위

사용자 편의를 최우선으로 하고 상용 DAW와의 조작 격차를 줄인다. 특정 제품의 단축키를 그대로 복제하기보다 Windows에서 익숙한 기본 조작을 채택하고, 앱 전체에서 같은 행동이 같은 결과를 내게 한다.

**완료 목표: EXE를 열고 샘플·악기를 골라 8마디를 편집한 뒤, AI 수정안을 비교·채택하고 저장·출력하는 일을 개발자 명령 없이 끝낸다.**

기존 기능을 먼저 실제로 사용해 보고 막히는 곳을 수정한다. 기능 수나 테스트 개수로 사용 편의성을 대신 판정하지 않는다. 라이브 싱크는 열린 프로젝트에서 유지되어야 하며 동기화를 위해 프로젝트를 다시 여는 방식을 도입하지 않는다.

이 문서는 [이전 마일스톤](next-milestones-2026-09-12.ko.md)의 다음 실행 순서를 사용자 작업 흐름 중심으로 조정한다. 기존 상세 사양과 미완료 요구는 유지한다. [DAW 조작 사양](daw-interaction-spec.ko.md), [AI 채팅 사양](ai-chat-milestones.ko.md), [도구 계약](ai-daw-tool-contract.ko.md)은 세부 참고 문서다. 구현 시 최신 HEAD와 작업 트리를 다시 읽고 이미 구현된 기능을 재작성하지 않는다.

## 현행 기준

소스와 기존 검증 기록을 읽은 결과이며 이 문서 작성 중 새 동적 검사를 수행하지 않았다.

| 영역 | 현행 | 이번에 필요한 일 |
|---|---|---|
| 작업 화면 | Browser/Rack/Playlist/Mixer, 패널 크기 조절·최소화·최대화·복원 | 실제 작업에서 포커스·배율·공간 배분·복원 확인 |
| 편집 | 피아노롤, 도구 선택, 노트 편집, 클립 조작, 우클릭 메뉴 | 창 사이 조작 일관성과 접근성 점검 |
| 재생 | 기본 재생·탐색·추적·화면 맞춤 | 클릭/드래그/정지/루프/줌 규칙 명확화 |
| AI | 선택 첨부, 질문·중단, 제안 확인·Apply, 대화 보존 | Preview·A/B·후보 선택을 일반 UI에 연결 |
| 비교·후보 | 렌더·후보 보관 로직 존재 | 진단용 스크립트 없이 사용 가능하게 연결 |
| 믹서 제안 | 효과·Send 변경 구현 | review-v5의 세 결함 수정 및 회귀 검사 |
| 실행 | EXE·패키징 경로 존재 | 프로젝트 선택·AI 연결을 포함한 사용자 실행 경로 점검, 오래된 가이드 수정 |

## W0. 실제 작업으로 불편 목록 확정

- [ ] 기준 커밋, 작업 트리 변경, EXE SHA-256, 장치·배율을 기록한다.
- [ ] 아래 최종 시나리오를 실제 마우스·키보드로 처음부터 따라간다. 기능 진입에 `--ui-script`를 사용하지 않는다.
- [ ] 막힌 단계마다 실제 행동, 기대 결과, 실제 결과, 우회 방법, 심각도를 기록한다.
- [ ] 문제를 작업 불가/오조작·데이터 위험/반복 불편/시각적 불편으로 구분하고 W1~W3에 배정한다.

**완료 조건:** 구현해야 할 것과 이미 있지만 찾기 어렵거나 조작이 불편한 것을 구분한 목록이 있다. 중간에 막힌 경우 그 뒤 단계는 미검증으로 남긴다. 사용자 청음을 자동 테스트로 대체하지 않는다.

## W1. 기본 편집 조작 통일

### 선택과 편집

- [ ] Playlist와 피아노롤의 클릭 선택, 추가 선택, 박스 선택, 선택 해제 규칙을 통일한다.
- [ ] 이동·복제·길이 조절 시 커서와 미리 표시로 결과를 예상할 수 있다. 스냅 상태와 임시 해제 방법을 일관되게 제공한다.
- [ ] Delete는 포커스가 있는 편집 영역의 선택을 대상으로 한다. 드래그 한 번은 Undo 한 번으로 되돌린다.
- [ ] 클립 더블클릭으로 해당 패턴의 피아노롤을 열고 편집 대상 패턴·채널이 보인다.
- [ ] 공유 패턴 편집의 영향과 Make unique를 사용자가 구분할 수 있다.

### 탐색과 재생

- [ ] 룰러 왼클릭은 재생 위치 이동, 룰러 드래그는 구간 지정으로 일관되게 동작한다. 선택 구간과 루프 활성 상태는 별도로 표시한다.
- [ ] 재생·정지·재개·처음으로 이동의 결과를 고정하고 툴팁/가이드에 설명한다. 재생 중 seek도 확인한다.
- [ ] 스크롤·줌의 방향과 보조키를 창 사이에서 통일한다. 전체/선택 영역 맞춤과 이전 줌 복귀를 쉽게 찾는다.
- [ ] 수동 탐색과 재생 추적이 서로 화면을 뺏지 않게 한다.

### 메뉴·수치·포커스

- [ ] 주요 대상의 우클릭 메뉴는 대상과 선택 범위에 맞는다. 메뉴를 열거나 취소하는 것만으로 음악이 바뀌지 않는다.
- [ ] 노브·페이더에 수치 입력, 초기값 복원, 미세 조절을 일관되게 제공하고 단위·현재 값을 표시한다.
- [ ] 채팅·이름·수치 입력 중 Space/Delete/Enter/Home 및 편집 단축키가 DAW 명령으로 새지 않는다. Escape로 취소할 수 있다.
- [ ] 패널 최소화·최대화·닫기와 복원 후 크기·선택·작업 위치를 유지한다. 닫기는 음악 삭제가 아니다.

**완료 조건:** AI 없이 악기/샘플 선택 → 8마디 작성 → 이동·복제·노트 길이 수정 → 믹서 조절 → Undo/Redo → 저장·출력까지 실제 조작으로 끝낸다. 각 조작의 기본 규칙은 한 장의 사용자 가이드에 정리한다.

## W2. 작업 상태와 자주 쓰는 기능을 알아보기 쉽게

- [ ] 선택 대상, 활성 패널, 편집 도구, 스냅, 재생 위치, 루프 범위를 색상만이 아니라 텍스트·형태로도 구분한다.
- [ ] 대상별 우클릭과 가까운 도구 모음에 반복 작업을 배치한다. 비활성 기능은 가능한 범위에서 이유를 설명한다.
- [ ] 저장·외부 변경 반영·렌더 진행·실패 상태에 다음 행동을 안내한다. 사용자 문구에 revision 등 내부 용어가 꼭 필요한지 검토한다.
- [ ] 100/150/200% 배율과 작은 창에서 글자·버튼·메뉴가 잘리지 않는지 실제로 확인한다.
- [ ] 프로젝트 열기/선택/복사/재개를 사용자가 앱에서 수행할 수 있는지 점검하고 부족한 경로를 연결한다.

**완료 조건:** W0에서 발견한 반복적인 메뉴 탐색, 모호한 선택, 포커스 혼동, 잘림 문제를 해결하고 동일 시나리오로 확인한다. 별도 테마 시스템이나 새로운 그래픽 자산은 실제 필요가 확인된 경우에만 추가한다.

## W3. AI 수정 비교를 화면 안에서 완성

### 선행 결함 수정

[review-v5](review-v5-2026-09-13.ko.md)의 R1~R3을 먼저 해결한다.

- [ ] 기존 Send 변경에서 preview와 apply의 대상별 Send 수·최종 level이 같다.
- [ ] main output과 Send를 함께 검사하고, 한 제안의 여러 변경으로 생기는 순환도 쓰기 전에 거절한다.
- [ ] Send와 EFFECT가 섞여 있어도 효과 순번 이동이 정확하다.
- [ ] 위 조건에 회귀 검사를 추가하고 한 번 Undo와 변경 거절 시 프로젝트 보존을 확인한다.

### 사용자 흐름

- [ ] 선택 영역/노트/Insert → 우클릭으로 AI 첨부 → 질문이 자연스럽게 이어진다.
- [ ] 첨부 카드에서 범위와 대상이 보이며, 이동·갱신·제거할 수 있다.
- [ ] 제안에서 변경 요약과 공유 패턴의 영향 범위를 확인한다.
- [ ] Preview 버튼, 진행·취소·실패 상태, 원본/제안 재생을 제공한다. 같은 비교 구간을 유지하고 어느 쪽이 재생 중인지 표시한다.
- [ ] 후보 목록에서 이전 제안을 선택해 다시 비교한다. 오래된 후보는 현재 곡에 그대로 적용할 수 있는 것처럼 표시하지 않는다.
- [ ] 비교 후 Apply와 한 번 Undo로 전체 변경을 채택·복원한다. 사용자가 그 사이 편집하면 오래된 제안의 적용을 거절하고 다음 행동을 안내한다.
- [ ] 외부 AI 구조를 유지하되 연결 여부·모델·문제 원인을 화면에서 확인한다. 이 시나리오에서 매번 셸 명령을 입력해야 하는 연결 과정은 앱의 시작/연결 경로로 해결한다.

**완료 조건:** 실제 모델로 노트 제안을 받고 화면에서 A/B → Apply → Undo를 완료한다. Insert 제안도 지원되는 효과로 확인한다. fixture는 오류·경계 검사용이며 실제 모델 사용을 대신하지 않는다. 오디오를 모델에 보내지 않는 현행 제한을 청음 가능한 AI처럼 표현하지 않는다.

## W4. 한 실행 파일로 최종 수용 검사

다음 순서를 진단 스크립트나 JSON 수동 편집 없이 수행한다. 외부 변경 반영 검사는 이 시나리오와 별도의 회귀 검사로 수행한다.

| 단계 | 통과 조건 | 결과/증거 |
|---|---|---|
| 1. EXE 실행·프로젝트 선택 | 개발 도구 없이 작업을 시작한다 | 미검증 |
| 2. 악기·샘플 선택 | 로드하고 소리를 듣는다 | 미검증 |
| 3. 8마디 작성 | 패턴 배치와 노트 편집을 완료한다 | 미검증 |
| 4. 편집·탐색 | 선택/복제/길이/루프/줌/Undo가 예상대로 동작한다 | 미검증 |
| 5. 믹서 조절 | 효과와 Send를 편집하고 결과를 듣는다 | 미검증 |
| 6. AI 연결·영역 질문 | 화면에서 연결 상태와 첨부 범위를 확인한다 | 미검증 |
| 7. 제안 비교 | 원본과 제안을 같은 구간에서 듣는다 | 미검증 |
| 8. 채택·Undo | 제안 전체가 적용되고 한 번에 복원된다 | 미검증 |
| 9. 저장·WAV 출력 | 파일과 앱의 결과를 확인하고 듣는다 | 미검증 |
| 10. 종료·다시 열기 | 음악·패널·프로젝트 대화가 복원된다 | 미검증 |

같은 EXE 해시로 관련 자동 회귀 검사도 순차 실행한다. 앱 단일 인스턴스를 점유한 다른 작업과 충돌하면 검사 환경 문제로 기록하고 임의로 다른 작업을 종료하지 않는다. 이전 빌드의 통과 기록을 이번 빌드 결과로 옮겨 적지 않는다.

실제 VST 악기·효과로 저장/재시작 및 preview 상태 복원을 확인한다. 비결정적 렌더는 바이트 동일성 대신 상태·범위·허용 오차·청음을 사용한다. 미검증 장치/플러그인/provider는 지원 확인 대상으로 별도 표시한다.

**최종 완료:** 위 열 단계가 사용자 경로로 통과하고, 작업을 막거나 데이터/적용 결과를 잘못 만드는 결함이 남아 있지 않다. 최신 실행법·단축키·AI 연결법 문서를 실제 화면과 일치시킨다.

## 진행 순서와 산출물

W0 → W1 → W2 → W3 → W4. W3 선행 결함은 W1보다 먼저 수정해도 된다. UI 연결은 기존 서비스·렌더·후보 보관 로직을 재사용한다.

각 작업 완료 기록에는 변경한 사용자 행동, 관련 파일, 자동 검사 결과, 실제 조작 결과, 남은 제한을 적는다. 구현 완료/자동 검증 완료/실사용 검증 완료를 따로 표시한다.

이번 범위에서 기본 조작 체계를 여러 DAW별로 복제하거나, 새 AI 변경 종류·오디오 이해·복잡한 연결 관리 기능을 넓히는 일은 우선하지 않는다. 사용자 시나리오를 막는 문제가 먼저다. 후보·메모·모델 관련 기존 장기 요구는 삭제하지 않고 후속 마일스톤으로 유지한다.
