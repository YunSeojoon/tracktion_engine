## R1 · P1 — 실패한 A/B가 재시작 후 정상 비교로 복원된다

위치: `examples/CoCompose/Main.cpp:2349` (`restoreFinishedComparison`).

복원은 status가 객체인지, running=false인지, WAV 두 개가 존재하는지만 확인하고 `preview.paired=true`로 만든다. 그러나 `collectRenderResult`의 실패 경로도 `writePreviewStatus(false)`를 호출한다. 완료 여부를 나타내는 paired/success 필드는 파일에 저장되지 않고, 복원 시 limits의 오류나 각 파일 fingerprint도 검사하지 않는다.

재현 조건:

1. 첫 A/B를 성공시켜 두 WAV를 남긴다.
2. 다른 제안의 A 렌더는 성공하고 B 렌더는 실패하게 한다.
3. 현재 실행에서는 paired=false라 재생이 차단된다.
4. 앱을 종료하고 같은 프로젝트를 연다.
5. 실패 status의 running=false와 남은 두 파일 때문에 새 A/이전 B가 정상 비교로 복원된다.

영향: review-v6 R2의 혼합 비교가 프로젝트 재시작 경로에서 다시 발생한다. `running=false`는 성공을 의미하지 않는다.

수정 방향: 양쪽 성공을 명시적으로 기록하고 성공한 쌍만 복원한다. 시작/실패 시 이전 성공 표시를 무효화하며, 저장한 두 지문과 실제 파일의 일치도 확인한다. 구형 status는 완전한 비교임을 증명할 수 없으면 다시 렌더하도록 한다.

회귀 조건: 성공→다음 B 실패→재시작에서 Play A/B가 비활성 상태여야 한다. 정상 완료→재시작은 재생 가능해야 하며, 한 WAV 교체/누락도 거절한다. 렌더 중 같은 실행에서 차단되는 검사만으로 대체하지 않는다.

## R2 · P2 — 버스 Insert의 비교 범위가 여전히 도입부로 돌아간다

위치: `examples/CoCompose/Main.cpp:2287` (`previewFromThePanel`의 touchedInserts 탐색).

새 범위 계산은 각 채널의 직접 할당 Insert가 touchedInserts에 들어 있는지만 확인한다. 그 Insert의 output이나 Send를 통해 도달하는 버스는 탐색하지 않는다.

재현 조건: 33박부터 연주하는 악기를 Insert A에 할당하고 A→B로 Send 또는 main output을 연결한다. B에 리버브를 두고 B의 이펙트/파라미터 변경을 제안한다. B에 직접 할당된 채널이 없으므로 범위를 찾지 못하고 0~8박으로 돌아간다. “Nothing plays through that insert” 안내도 사실과 다르며 후속 렌더 안내로 덮인다.

영향: 직접 할당된 Insert에 대한 review-v6 R3은 개선됐지만, 일반적인 리버브 버스/그룹 버스 작업에서는 바뀐 소리가 나는 구간을 듣지 못한다.

수정 방향: output·Send를 포함한 라우팅에서 해당 Insert로 도달하는 소스를 찾는다. 비교 구간을 사용자가 지정할 수 있게 하고 실제 범위를 표시한다. 시퀀스 존재만으로 연주를 판단하지 말고 빈 시퀀스도 제외한다.

회귀 조건: 뒤쪽에서만 연주하는 채널의 직접 Insert, Send 버스, output 그룹 버스를 각각 검사하고 해당 연주 구간이 비교에 포함되는지 확인한다. 정상 렌더 종료만으로 통과시키지 않는다.
